# Static receipt/cache preflight

Both c18 control and candidate use the same contract. `docs/api.md` states that `receipt.layoutOptimization` reports work/strategies accepted **during that execution** and cached positioned output can perform no new optional work.

`positioning.ts:196` enters `withLayoutOptimizationBudget(request, ..., position, true)` on every balanced request. `optimization-budget.ts:25` creates a fresh budget initialized to zero and records it against that request in `finally`. A positioned-cache hit at `positioning.ts:134` returns retained geometry/projection and copies graph layout decisions. It does not replay producer counts, attempt counts or selected strategies. `receiptOf` reads the evidence of the current request, rather than evidence of the original geometry-producing request. Thus the cold optimized product can report primary1/additional1/attempt1/selected['prefer-model-order'], while its identical warm SVG reports primary0/additional0/attempt0/selected[]. This is permissible documented request accounting, already present in c18. `selected` here does not re-describe the historical producer of cached geometry.

`recordLayoutProducer` still charges a logical producer when only the lower ELK-result cache hits; its comment is consistent with the upper positioned-cache behavior. The actual placement producer is skipped entirely on an upper hit.

The same static inspection corrects a preparation mistake: `positioning.ts:110` checks AGENTIC_MERMAID_ELK_CACHE before permitting its upper cache. Cache0 disables both positioned and ELK result reuse. Cache1 enables the normal public caches subject to key/weight admission. No observer is added to prove a hit during timing; operational differences are labeled consistent with this documented path, with complete raw fields retained.

The unchanged receipt-worker's `entireReceiptExactWarmup` remains literal byte equality. Postmeasurement byte controls retain the exact SVG/receipt flags and explicit before/after JSON differences. Only the four named layoutOptimization paths can receive the documented-accounting classification; additionalProducerLimit, decisions, digests, paint, diagnostics and every other field remain outside that classification. Both default controls still require exact candidate/control SVG bytes. No receipt is normalized before comparison and no current candidate result has been measured during this static preflight.
