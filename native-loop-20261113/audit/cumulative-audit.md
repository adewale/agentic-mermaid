# Native and shared pipeline audit — working evidence

Base source: `68986ba8e3b76ad99dad44c6ec8d43475cc5e12f`. Production is read-only for this reviewer. This document records proposals and disproved proposals, not a claim that every source file or input has been exhaustively verified.

## The finite obligations

Native-relative geometry tradeoffs already measured are the nested/parallel/Unicode flowchart (9 versus 7 bends and larger area, with shorter wire), architecture ports/groups (358.133 versus 352 wire, equal area), and the small Usecase example (2 versus 0 bends and slightly longer wire, with smaller area). Historical forest wire, Requirement TB/BT area and Sparse256 area comparisons remain separately unresolved where the original input or matched evidence is unavailable. A metric tradeoff is not automatically a connectivity defect. Universal dominance in wire, bends, area, spacing and authored ordering cannot be inferred from one layout algorithm.

The owner's under-100ms requirement is an absolute full-consumption target: historical cache0 chain100 Native109.55ms does not meet it. Chain300's 400k proof limit is a shared capacity gap (both engines unknown), not a demonstrated Native rendering failure. Missing exact-contact/axis/glyph-collision observations are unknown. The same distinction applies to partial paint certification. Mixed/demo/editor fetched bytes and flow request counts are separate delivery obligations, despite Native's substantially smaller isolated graph closure.

## Cumulative proposal order

1. **Remove the first cause of the newly reproduced compound support loss.** The three-group row, five leaves per group, with A→B permutation `[4,2,0,3,1]` and B→C permutation `[1,3,0,4,2]` has now been run in all four directions through existing observers. Native rejects LR/RL at visibility-expansion capacity and BT with no bounded corridor; ELK returns all four with passing complete paint/meaning. TB Native returns with24crossings/53bends versus23/28, but shorter wire/smaller area. Full evidence: [compound-permutation/REPORT.md](compound-permutation/REPORT.md). The trace shows independent child ordering loses the permutation at `agentic-compound-core.ts:85–105`; existing global nesting declines acyclic quotients at `native-nesting.ts:60`. However, identity/subset controls must distinguish ordering from small-grid strategy capacity before implementation. The previous unconditional global-DAG trial caused9/25 quality regressions and remains withdrawn. Native already has global nesting; prefer a structurally justified extension or removal of redundant routing work, preserve all caps and mixed-direction/model-order compatibility. Actual ink connectivity, group membership, label attribution, directions and adverse costs remain obligations.

2. **Evaluate no-op budget measurement at the owned route-contract transaction.** Source-mapped profiles identify shared `assessLayoutGeometry` and `measureRubricMetrics` on chain100/300. `src/layout/pass.ts` captures all declared before/after metrics; `src/layout/legacy-completion.ts:214` asks the route-contract pass for straight/bends/portRate and conditional hard/crossings/endpointApproaches/opposingOverlaps. Hypothesis: defer a pass's baseline measurements until its first real geometry change, leaving a certifying no-op with no budget delta to compare. This is not stale rubric reuse. It is not implementation-ready: points mutate through `setRoutePoints`, but labels and route certificates also affect scoring, callbacks/getters remain live, and a valid first-change hook must precede every relevant write. If this needs a new broad trust flag, many hooks, or changes public read order, stop. The measured self costs are an upper bound on work that can be removed, not an additive or end-to-end speed promise; this alone is not yet shown sufficient for the chain100 target.

3. **Unify placement constraints before route repair where a named loss proves the need.** Native's median sweeps and long-channel compaction precede final port selection (`src/layout/agentic-layered-core.ts`, cross-coordinate/port sections). ELK's BK implementation first aligns blocks and then explicitly shifts within blocks to align actual ports before compaction. A port-offset-aware block constraint could replace successive alignment/repair decisions, but only after tracing the named Usecase/architecture/nesting example to this stage. Do not introduce a wholesale BK rewrite on the basis of a paper alone. Preserve group borders, occupied widths, authored fixed sides, rank feasibility, stable order, loops, labels and real shape contacts. Compare corrected BK/Dagre approaches, not the flawed original compaction pseudocode. Runtime/memory benefit is unmeasured; arrays/CSR are already used in parts of Native.

4. **Payload boundary investigation, not another loader rewrite.** Inspect the existing built module graph for the flow request-count and mixed/demo/editor byte regressions; identify an actual unnecessary import or duplicated shared closure before changing a boundary. Existing browser-lazy family loading and prior style split/revert experiments preclude assuming a new loader or more chunks helps. Keep CSS, definitions and style ownership intact; count fetched compressed bytes and requests on the same host/build before claiming an improvement. No additional runtime cache is proposed.

## Withdrawn first experiment

The exact finite-axis miss gate in `src/shared/edge-crossings.ts` is behaviorally supported but is being withdrawn. The fan100 probe found 29,106/67,890 general-intersection calls were same-axis misses; chains had zero opportunities. Finite **spans**, not just finite endpoint coordinates, are required because ±1e308 differences can overflow. Ownership trace and raw numeric parity support the narrow gate, but the isolated unprofiled costs do not support retaining it: Sol reports Native fan stock128.42→125.52ms while full155.88→163.11ms and cold319.98→336.87ms worsened; ELK full348.48→383.02ms and cold760.89→810.13ms worsened; Native chain100 full101.90→105.37ms and first edit134.86→174.94ms worsened. These are this run's exploratory medians, not historical-host comparisons. Do not re-run favorable gate variants. Final complete-product equality and raw cost archive belong to Sol's implementation directory.

## Primary-source and peer lessons

- [Pele1.9.0 compound tests, commit e7f092a](https://github.com/obsidianmd/pele/blob/e7f092a4de147cc32210913c20e36eaa5fcd0ef1/tests/layout/compound.test.ts#L588) verify consistent far-side port order in TB/LR and a three-group permutation with zero routed crossings. [Its compound implementation](https://github.com/obsidianmd/pele/blob/e7f092a4de147cc32210913c20e36eaa5fcd0ef1/src/layout/compound.ts#L597) uses a bounded same-direction flat ordering hint, then tests actual routed crossings and restores a prior geometry if a refinement fails. Curved versus stepped ink is distinguished in its tests at570–582. These are verified source/test intentions, not measured Pele superiority on our corpus. The public1.9 source is now available; the missing pinned full rendering comparison remains missing.
- [ELK authors, 2023, §3–4](https://arxiv.org/html/2311.00533v1): independent bottom-up child layouts can force incompatible hierarchical port order. Considering cross-hierarchy destinations addresses some cases but conflicts with several direction/order strategies. Explicit phase preconditions and processor dependencies matter; ELK computes rectangle/route geometry, not final glyph/marker/CSS correctness. Transfer the causal boundary, not its entire option system.
- [ELK BKNodePlacer, v0.11.0 commit54123e8](https://github.com/eclipse-elk/elk/blob/54123e884b1ae743b453260f713b20c9bf5787f2/plugins/org.eclipse.elk.alg.layered/src/org/eclipse/elk/alg/layered/p4nodes/bk/BKNodePlacer.java#L213) invokes inside-block shifts for actual ports before compaction. Preconditions include proper layers, optimized node order and arranged ports. This source pin is not an assertion that a particular elkjs artifact was built from exactly this Java revision.
- [Dagre1.1.8 nesting graph, commit7e4d15f](https://github.com/dagrejs/dagre/blob/7e4d15f191678f7f05f3c86d9071a193230e7e00/lib/nesting-graph.js) uses top/bottom borders, nesting depth and minimum spans; [coordinate placement](https://github.com/dagrejs/dagre/blob/7e4d15f191678f7f05f3c86d9071a193230e7e00/lib/position/bk.js#L206) explicitly substitutes a block-graph two-sweep compaction for the original BK compaction. Native already has analogous border and bounded minimum-span machinery; avoid duplicating it.
- [Brandes–Köpf original author PDF](https://kim246.wwwdns.kim.uni-konstanz.de/publications/bk-fshca-01.pdf) gives fast coordinate assignment once layers/order are fixed. [The2020 erratum](https://arxiv.org/abs/2008.01252) corrects two compaction errors without an asymptotic penalty. Its linear complexity concerns the proper expanded graph, not parsing, dummy expansion, routing, paint capture or receipt production.
- [Sander's1996 author exposition](https://www.site.uottawa.ca/ordal/papers/sander/node21.html) explains why independent frames miss global cross-frame relationships and why nondividing layouts require consecutive members and consistent frame order across ranks. Global treatment costs more and limits independent hierarchy parameters. This supports a restricted existing-path extension, not unconditional flattening.
- [Barth–Mutzel–Jünger2004](https://www.jgaa.info/index.php/jgaa/article/download/paper88/2877/2684) reduces bilayer straight-edge crossing counts to inversions. Native's rank-order crossing score already uses this class of indexed counting. It cannot replace final polyline/curve/marker intersection semantics; counting straight two-layer inversions and counting final painted crossings are different problems.
- [Eades–Lin–Smyth1993 publisher record](https://www.sciencedirect.com/science/article/pii/002001909390079O) provides a linear-time feedback-arc heuristic for the stated sparse/simple graph domain. The institutional full-text link was403, so detailed pseudocode was not inspected. [Sugiyama–Tagawa–Toda1981](https://doi.org/10.1109/TSMC.1981.4308636) is the primary historical reference; IEEE full text presented a robot check. Do not attribute unverified algorithm details to either source.
- [Mermaid12.2 pinned geometry](https://github.com/mermaid-js/mermaid/blob/1fb7869866dd619168d840291c9c54b4f129758b/packages/mermaid/src/rendering-util/layout-algorithms/elk/geometry.ts) preserves an orthogonal departure axis when moving an ELK bounding-box endpoint onto a shape outline, falling back when it cannot prove the ray. This reinforces final shape-contact ownership, not pixel parity. [Beautiful Mermaid pinned layout](https://github.com/lukilabs/beautiful-mermaid/blob/2ac8bbbb060ca0a65a6a21f3200bd99b1587b488/src/layout-engine.ts) wraps ELK then applies layer alignment, shape clipping and bundling. It is a differentiated rendering pipeline, not an independent layout algorithm or a correctness oracle.

## Coverage and limits

Reviewed relevant paths include Native rank/order/coordinates, compound/nesting, minimum-span ranks, measured route shortening and producer selection; graph completion and pass contracts; Usecase and Architecture geometry ownership; shared crossing and rubric costs; native drawing/capture, validation, writer/evidence and paint certification; browser-lazy entry points. This is targeted semantic inspection plus existing corpus evidence, not a proof of all source lines. Generic copy/scalar shortcuts, group-only validation, corrected rubric-order reuse, global/lane BVH/CSR and capture/source shortcuts already have adverse or insufficient evidence and remain stopped. Existing marker peer views are present. No new cache, cap, default, version or competitor performance claim is proposed.
