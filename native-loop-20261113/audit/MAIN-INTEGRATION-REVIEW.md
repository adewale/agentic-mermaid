The E×N whole-route/node enumeration and [N² node/node overlap loop at638](https://github.com/adewale/agentic-mermaid/blob/a2e5ddc927e7432affbc293b7996a74b5fe59003/src/layout-rubric.ts#L638) remain in the source, but their new end-to-end contribution is unmeasured.

## Cache interpretation after integration

Main also adds inter-call source normalization and appearance memoization in [`render-contract.ts:1584`](https://github.com/adewale/agentic-mermaid/blob/a2e5ddc927e7432affbc293b7996a74b5fe59003/src/render-contract.ts#L1584). Source reuse is bounded to 64 entries/4MiB estimated weight and the current family-routing revision, original descriptor and empty explicit Mermaid overrides; each request receives a fresh frozen top-level source object. Appearance reuse retains up to eight entries per remembered source and checks options, registry revision, prepared style/face identities and parser-observer policy. These are inter-call memoization, unlike the admission-total accounting above. Main also adds a four-entry probation tier bounded to one quarter of the existing 16MiB positioned estimate: up to 4MiB additional estimated positioned retention beyond the existing 128-entry tier. Finished SVG stays within the existing 8MiB drawing estimate. These are source-level bounds, not measured browser heap/RSS; deleting writer evidence and adding other retention cannot be reduced to a net memory claim without measurement.

`AGENTIC_MERMAID_ELK_CACHE=0` still disables the positioned/drawing and solver-result tiers, but **does not disable these new source/appearance caches**. Repeated cache0 full-request measurements can therefore skip normalization/appearance work that a fresh process or edited input still performs. Existing cold, first-edit and warm cells must retain their distinct meanings. No hit rate is inferred from this source review.

[`graphical-render.ts:224`](https://github.com/adewale/agentic-mermaid/blob/a2e5ddc927e7432affbc293b7996a74b5fe59003/src/graphical-render.ts#L224) additionally reuses finished, secured SVG bytes and diagnostics for a retained drawing with the same finishing identity; the drawing tier accounts for those retained bytes. Main removes the separate writer-tag-evidence implementation. Neither change authorizes skipping final admission of newly produced or changed bytes. The new warm shortcut cannot establish the cold full-consumption target.

The layout-debug cache identity now reads a closed, typechecked list of relevant switches rather than enumerating the entire host environment. C4 generated identity allocation is plain cloneable state rather than an embedded closure. These are concrete Main simplifications; their cost and payload effect have not been measured in this audit.

## What remains authorized after Main integration

Run the existing owning tests and final product observers against the merged source, including the compound fix's real-terminal custody, numeric leads, getters/custom sizes, Class legacy policy, cap boundaries and all16 actual marker/foreign-shaft products. A textually clean merge is not evidence of equivalent pipeline behavior. Then obtain a fresh mapped profile and the same complete-product cold/edit/cache0 timing cells before choosing another performance intervention. The older axis-adaptive candidate-enumeration idea is now a **residual hypothesis**, not an implementation instruction; Main's route-box filter may already consume most of its useful ceiling. Likewise, do not repeat the stopped copy/XML/reuse experiments or add another cache around work Main has already removed. The remaining N² loop and native paint capture remain possible investigation sites only if the new profile shows a material contribution.

This review found no demonstrated source overlap with the 11-file compound patch and establishes no new correctness defect or performance gain in Main. It preserves the exact source pins and the need to requalify shared ownership, budgets, diagnostics and fully consumed products after integration.
