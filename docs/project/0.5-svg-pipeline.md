# Typed SVG pipeline campaign

This work continues PR #433. It measures new post-layout work against the exact
requested #431 revision `a9d1551da27ddab542a1ae96329464ad65725448` and against
`bfaad177a29d29a450525813caea9c386ee07304`, the immediate pre-pipeline revision.
The requested revision is an earlier #431 head; the merged #431 head is
`d0fcfeb4a53bdd5817fcccc1c0166220900573d4` (merge `30f0af5d63e460c8bd3de88358414f2c7857a2c6`).
The intervening history and production differences are retained in the evidence.
Existing #431 admission, freezing, byte-budget, receipt hashing, color-resolution,
lazy-ELK and cache improvements are baseline work, not gains from this campaign.

## Fixed measurement contract

Both primary sides start with `AGENTIC_MERMAID_ELK_CACHE=0` and
`AGENTIC_MERMAID_SCENE_ASSERTIONS=0`, without the unit assertion preload.
Assertions-on and cache-hit measurements are separate. Built and installed
artifacts establish startup/package claims; source stage measurements explain
costs. Post-layout measurements must start from equivalent positioned artifacts
and end with secured SVG plus the complete, bound public receipt. Layout,
corpora, goldens, deadlines and release gates remain unchanged.

The pinned build packed 192 verified files. Its tarball SHA-256 is
`804a14b0ddf5bad437cb2f28e90e31d080425c6ca39eb0b981ca58352ad35c28`.
`/workspace/svg-pipeline-evidence/pinned-provenance.json` records the lockfile,
runtimes, build configuration, environment and machine limits; the evidence
also retains the actual package, lockfiles and reproducible command logs.

The initial identical-installed-package A/A comparison completed all 557 inputs
in five interleaved rounds. Correctness and allocation gates passed, but the
unchanged corpus timing gate failed at 1.44× and the architecture gate also
failed. This is a measurement repeatability failure, not a candidate regression
or improvement. Raw samples and the failed report are retained. Timing claims
require a repeatable comparison and uncertainty reporting; no gate is relaxed.

The prospective acceptance targets remain ≥20% custom-suite SVG time reduction,
≥30% matched-release allocation reduction, and roughly half the sequence/class/
ER/state post-layout time, with no reproducible family/startup/PNG/terminal/
memory/payload regression beyond measured noise. These are targets, not results.
The user-specified unchanged 18-case custom suite and Mermaid Dart/control
scripts have not yet been located; their evidence is incomplete until identified.

Each family migration is a complete vertical slice with owner tests and byte
comparison before integration. The lead reviews all contributions. Trust-boundary
changes receive independent review and negative-control evidence. Documentation
consolidation and final packed-candidate verification follow implementation.
