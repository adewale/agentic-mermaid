# 0.5 performance and size investigation — 18 October 2026

Input for the 0.5 refactor: where time, bytes and memory go, measured at
`d9232aa` (main after #424); file:line references are at that revision. It
records evidence and hypotheses, not a backlog or a plan; `TODO.md` stays the
only queue. Delete this file once the 0.5 work has consumed it.

**Method.** CPU profiles (250 µs sampling) of the built Node package with
source maps, Node 22.22, on a shared 4-vCPU Linux sandbox that was also running
other jobs, so absolute times are inflated by an unknown factor; ratios
measured in the same session are more reliable. Stage timings and allocation
come from `bun run bench:micro --runtime node`. The Beautiful Mermaid 1.1.3
comparison ran on the same machine and in the same session. An A/A
`bench:micro` comparison of identical source (defaults, three rounds) spread
0.82–1.11×, so timing differences under ~20% are not resolvable here.
Allocation per call repeated to three digits. The findings describe `d9232aa`;
"After the first fixes" records what has changed since. The ELK option
variants were timed with ELK alone; their effect on layout quality is unknown.

## After the first fixes

Four changes on top of `b88768c` remove costs without changing output:
`check:output-identity` against `b88768c` found all 5,620 outputs
byte-identical.

- `graphemes()` splits printable ASCII without `Intl.Segmenter` (finding 6).
- Built-in admission copies its own Scene by reading own enumerable keys
  instead of property descriptors. Limits, prototype, cycle and sparse-array
  checks, the frozen null-prototype copy and validation are unchanged;
  shapes only a lowering bug could produce (symbol or non-enumerable keys,
  extra array properties, accessors) are no longer diagnosed on this path. External Scenes keep the
  descriptor path (finding 1).
- A built-in backend proves conformance at its first draw, render or
  descriptor read instead of at import; one that fails still never draws
  (finding 4).
- The start-tag scanner tests whitespace without a regex call per character
  (finding 2).

## After the post-layout pipeline work

Seven changes after #427 take option A from the 0.5 discussion: make the
work after layout cheap, then load ELK lazily and cache its results.
`check:output-identity` found all 5,620 outputs byte-identical against
`df0b802`, and again after rebasing onto `db5ecd2`. The measurements below
were taken against `df0b802`.

- Built-in Scene admission in an ordinary render no longer re-derives
  connector terminal projections, compares marks with their serializations,
  or runs the security policy over each mark's serialization (finding 1).
  They still run for the requests `verify` lowers, for `layoutSafety:
  'strict'`, for the connector Scene ASCII draws from, and under
  `AGENTIC_MERMAID_SCENE_ASSERTIONS=1`, which the unit-test preload sets.
  External Scenes keep every check, and the final output-security gate still
  inspects every emitted SVG. A default render's paint certification now
  assumes the lowering is consistent, which the tests and `verify` check.
- Built-in Scenes are frozen in place instead of copied, under the same
  limits and checks (finding 1). Keeping the lowered objects, rather than
  avoiding the copy's work, is what saves time: under Node a copy into
  ordinary objects was only a few percent faster than the null-prototype
  copy, while freezing in place was about a quarter faster.
- The final byte-budget check skips counting for an SVG of at most a third of
  the budget in UTF-16 units; the receipt's FNV-1a-64 runs in 32-bit halves
  instead of BigInt (30 ms to 0.5 ms for a 200 KB SVG under Bun); colour
  inlining skips its second whole-document pass when nothing is left to
  resolve (finding 2).
- elkjs loads at the first ELK layout under Node and Bun (finding 3). The
  published Node build imports `#elk-constructor`, which `package.json`
  resolves to a `createRequire` loader under the `node` condition and to the
  bundled constructor elsewhere. A never-called lazy CommonJS wrapper around
  the bundled ELK saved nothing under Node: the cost is parsing its 1.6 MB.
- ELK results are cached by input graph (finding 8): 64 entries and 1 Mi
  key code units, roughly 4–9 MiB, least recently used first out. The
  benchmarks set `AGENTIC_MERMAID_ELK_CACHE=0` (a global of that name in a
  browser), so their repeated renders still time ELK.

### Exploring other layout caches

A render, `verify` or `layoutMermaid` call runs ELK once per layout attempt:
more when certification tries a second candidate (mesh50 runs two), when a
class namespace title wraps, or when ELK fails and the option ladder retries.
ASCII never runs it. ELK caching therefore pays mostly across calls: a
repeated render, or a render after `verify` of the same diagram, as an
agent's edit step does.

- **Positioned-layout memo** keyed by the request's `sharedRequestDigest`.
  Prototyped, not shipped. With the ELK cache on, a repeated render (Bun,
  from source) still spends 40–75% of its time in our own layout (mesh50 186
  of 250 ms, tree50 42 of 105 ms, flow5 14 of 29 ms); the memo took those
  renders to 67, 54 and 16 ms. In the agent edit workflow (`verify` then render of each edited
  diagram) it hit once per step but saved nothing measurable beyond the ELK
  cache, because that diagram's own layout is cheap. Its key would have to
  cover every input layout reads besides the request: eight `APL_*`
  environment flags, two of which tests toggle between renders of one
  diagram, and any other process-wide state. The result would also be shared between
  renders, whose lowering now freezes what it references. Worth revisiting
  with an explicit, complete key if repeated identical renders matter.
- **Cross-render text measurement**: preparing and measuring text is 2.5–4%
  of a warm render (class80, seq20), so a memo could save at most that. Not
  built.
- **Verify re-render reuse**: `verify` already lays out once for its
  render-parity checks (finding 8); a render of the same diagram after it now
  reuses that ELK result, but still repeats our own layout and drawing.

## After the single writer

Changes after #431, from the solutions note that followed the community
research:

- **One writer.** Every shape, text and connector is written from the typed
  fields paint certification reads (`src/scene/svg-writer.ts`); families no
  longer attach SVG strings, and their stylesheets no longer paint typed
  marks. A default render's certificate therefore describes the SVG it
  ships, and `verify` no longer compares marks with their serializations
  (under Bun, that comparison was 4–21% of `verify` on the micro workloads: 2 ms of 32
  for flow5, 33 ms of 240 for class80, 29 ms of 139 for er40). The fidelity
  module stays as the tests' oracle over the corpus. Escaping returns its
  input when nothing needs escaping, which cut about a tenth of the scene
  stage under Bun.
- **Admission walk.** The built-in Scene walk charges an upper bound (three
  UTF-8 bytes per UTF-16 unit) instead of counting text bytes, and counts
  exactly only when the bound would trip a limit. Under Node it changed
  `scene:lower-admit` by 0.96–0.97×, within noise: freezing, not counting,
  dominates the walk.
- **Error origins.** `verify` attributes a render-path failure to the source,
  its configuration or the engine (`INTERNAL_ERROR`); see the changelog. No
  timing effect.
- **ELK options.** A sweep of thoroughness, greedy switch, post-compaction,
  node placement and model-order settings found nothing to adopt: every
  setting that saved at least 10% of ELK time on two workloads also
  regressed the layout tracker, and the settings that left layouts unchanged
  saved nothing measurable. Flowchart already runs thoroughness 3; lower
  values help only mesh50 (−27% ELK at 1) and cost crossings (70 → 103).
  Class and ER lay out identically at thoroughness 3 or 1 but crossing
  minimisation there is only 3–6 ms. `postCompaction=NONE` saves 16% of ELK
  on state80 alone and regresses five tracker cases. `nodePlacement=SIMPLE`
  regresses 38.

## Findings

1. **Built-in Scenes are admitted as if they were hostile input.**
   - `admitFamilyScene` (`src/scene/admission.ts`) runs
     `snapshotBoundedExternalData` on every built-in render. It is a deep copy
     and freeze that reads descriptors one at a time, designed for caller
     Proxies. `assertValidSceneDoc` then runs over the whole document.
   - class80: snapshot 46 ms / 20 MiB, validation 53 ms / 34 MiB, lowering
     plus admission 121 ms / 64 MiB.
   - seq20: 7 ms + 10 ms, against 0.1 ms for Beautiful's entire render.
   - *Hypothesis:* build built-in Scenes as validated immutable values, and
     check their invariants in tests and `verify`. Keep the hostile-input path
     for `family:` extensions and external Scenes.
2. **Two representations, then repeated string reprocessing.**
   - Lowering writes an SVG string for each node, re-tokenizes it to
     canonicalize it, and stores it in a WeakMap side table
     (`src/scene/serialization.ts`). Admission transfers the strings to the
     frozen copies; the default backend just joins them (0.1 ms).
   - The document then goes through color inlining, text fitting, id
     namespacing, accessibility, style scoping, optional compaction and output
     security (`src/graphical-render.ts`). A byte budget is asserted after each
     step.
   - `scanSvgStartTags` processes 8.3× the output bytes per render (1,522 calls
     for class80). `inlineResolvedColors` alone takes 23 ms / 16 MiB on class80:
     up to ten regex passes per CSS context, plus extra full tag scans.
   - *Hypothesis:* one emitter from the typed Scene that writes resolved
     colors, scoped styles and escaped attributes directly, with at most one
     final verification scan.
3. **ELK: eager, heavyweight, and configured expensively.**
   - `src/elk-instance.ts:19` imports ELK statically for all 17 families,
     though only 5 use it. Import costs 135–148 ms and ~25 MiB.
   - The ELK chunk is 458K of the 685K gzip bytes the lazy browser entry
     loads for a first flowchart. The remaining 227K is about as much as
     Mermaid loads for its whole first flowchart (224K, `docs/comparison.md`).
   - ELK alone takes 10.5 ms for 5 nodes and 137 ms for mesh50.
   - With model-order constraints removed, mesh50 drops from 174 to 98 ms.
     Removing post-compaction takes the 5-node case from 11.5 to 7.4 ms.
   - mesh50 lays out twice, because certification tries a second candidate
     when crossings remain (`src/layout/certification.ts`).
   - *Hypotheses:* lazy `createRequire` inside `ensureElk`; option sets chosen
     against the layout rubric rather than by default; a non-ELK path for
     trees and small graphs.
4. **Self-tests run at every import.**
   - `src/scene/builtin-backends.ts:18` runs `runBackendConformance`: it
     renders fixtures through three backends (rough.js included) and validates
     them. Warm that is 50 ms / 26 MiB per pass; cold it is ~145–230 ms.
   - The family registry is also built and checked at import
     (`src/agent/families.ts`).
   - The browser pays the same cost through `src/graphical-render.ts:8`.
   - *Hypothesis:* check built-ins in CI; at runtime, run conformance only for
     third-party registrations.
5. **One shared, unminified 3.44 MB chunk behind every Node entry.**
   - `dist/index.js` imports only `chunk-6CEQKPPR.js`. The cause is the
     side-effect import `src/index.ts:20` (`./agent/families.ts`, which pulls
     in 17 typed bodies) plus the ASCII re-export. `.`, `./agent`,
     `./agent/core`, the CLI and MCP all load it.
   - The chunk is 1.84 MB minified; only the browser builds are minified.
   - The package ships three builds (Node, IIFE, lazy): 11.1 MB of `dist`
     without source maps, with ELK embedded twice besides the `elkjs`
     dependency.
6. **Allocation-heavy data structures.**
   - `prepareDisplayText` makes one frozen object per grapheme cluster
     (13 KiB for a short label).
   - `graphemes()` runs `Intl.Segmenter` on pure-ASCII text: 25 µs / 4.5 KiB
     for a 38-character label under V8, and 36% of the typed tree50 parse.
   - Immutable snapshots are taken at every boundary.
   - The token arrays from repeated tag scans add more.
   - ASCII rendering spends its time in per-cell owner records (`place`,
     `overlay`, `admitOwners` in `src/ascii/terminal-document.ts`), with GC at
     16%.
   - GC is 7–16% of every profile.
7. **Dense routing repairs.** On mesh50, `directLaneBlockers` and `tryZRoute`
   (`src/route-contracts.ts`) take ~16% of the render, after ELK has already
   routed the edges.
8. **Verification repeats rendering.** `verifyMermaid` on tree50 takes 117 ms,
   about one full render, because it renders for parity. The two-node agent
   edit loop takes 30 ms.
9. **Retention to watch.** After warm-up, heap grows ~2.5 KB per distinct
   diagram and slows down (+8.7 MiB over the first 400 renders, then about
   +1 MiB per 400). This is not shown to be a leak. A heap-snapshot diff in a
   long-running MCP server would settle it.
10. **Look-alike helpers are mostly not duplicates.** The four `clamp`s nest
    `Math.min`/`Math.max` differently, so they disagree when `min > max`, and
    the XML/HTML escapers differ on quotes by design: merging either would
    change edge-case output. The two `scanTagEnd`s (`svg-structure.ts`,
    `custom-font-geometry.ts`) run the same scan and return offsets one apart,
    so they could share it behind an adapter. The real multiplier is
    representation: each family carries five eager forms (parser IR, agent
    body, positioned view, ASCII and SVG).
    - `bun run bench` (website samples) overlaps with `bench:micro`'s render
      cases.

The defensive layers exist for real reasons: hostile extensions and hosted MCP
input. The 0.5 question is where they run, not whether they exist.

## After layout-quality consolidation — 20 October 2026

These measurements compare a local, unmerged implementation on
`codex/consistent-diagram-quality` with
`1b1ba848445955f08869ff6369f482ce50618a95` (#437). They are historical evidence,
not current release claims. The policy and its limits live in
[`quality.md`](../quality.md#layout-priorities-and-their-limits) and the
[`layout rubric`](../design/system/layout-rubric.md).

The implementation shares crossing and label-conflict definitions, retains exact
public graph geometry, and removes inert invariant-check flags. Hard feasibility
remains mandatory; feasible candidates prefer readable titles, crossings, soft
label conflicts, avoidable bends, canonical ports, symmetry, then area.
The initial recommendation to put all soft label conflicts before crossings was
rejected after it produced a larger, less symmetric mesh with more crossings.
The final engine chooses a bundled placement first, then compares at most one
unbundled route proposal using that placement's ELK result. It avoids the initial
placement/routing cross product, retains specialized fan routing, and leaves
parallel-edge graphs with their specialized lane owners.

Each revision produced its own geometry in a fresh worker; both were assessed
with the candidate's same metric and meaning definitions. This separate,
artifact-only audit used 94 existing graph witnesses plus one minimal skip-edge
witness. It is distinct from the checked-in visual rubric; its State workload
exercised raw graph layout rather than the complete native family projection.

| Across 95 fixtures | Before | After |
|---|---:|---:|
| Successful layouts and SVGs | 95 | 95 |
| Hard, geometry or meaning violations | 0 | 0 |
| Proper crossings | 79 | 67 |
| Label-conflict pairs | 43 | 42 |
| Raw interior route vertices | 786 | 787 |
| Scored avoidable bends | 314 | 363 |

Four fixtures changed, representing three distinct structural patterns; 91
retained identical geometry. Identities and membership were preserved. The mesh
changed from 70 to 62 crossings and four to three label conflicts, retaining
placement, area and measured symmetry, while using fewer canonical ports.
Bundle-owned bends are exempt from scoring, so the scored-bend increase is not
49 additional geometric vertices. No independent human preference study was
performed. Separately, one official corpus drawing lost its single crossing;
