## Reproduction and preparation

AM's maintained product controller is `eval/benchmark/unified/run.ts`. Inspect prerequisites without collecting new timings:

```sh
bun run bench --list --profile full --suites release,endpoint-marker,output-identity
```

For an exact release comparison, select both tarballs and both SHA-256 digests. A supplied baseline tarball takes precedence over `--baseline`, which may also be supplied for a different diagnostic; a missing tarball digest blocks release measurement.

For endpoint-marker checks, use `--baseline-checkout` and `--candidate-checkout` with actual clean Git checkout roots and built `dist/agent.js` entries. These paths are distinct from installed release-package directories. Existing `--baseline` and `--package-root` inputs remain fallbacks for callers already using built checkouts. Admission checks cleanliness and entry existence; it does not certify that a caller-supplied build matches its source revision.

Output-identity extraction already copies the current evaluation inputs and policy into scratch while taking production source and fonts from the selected revision. Its existing regression exercises executable sibling fixtures and checks that extraction leaves the shared Trident library untouched. The older missing-fixture repair is therefore superseded by current AM code.

For a new AM PR campaign, inspect the product-owned runner:

```sh
bun eval/benchmark/unified/pr-campaign.ts --help
```

Use a new output directory and the exact selected artifacts. The current controller does not reproduce the archived strict producer's clock automatically. Reusing old samples or assigning old measurements to a new head would invalidate the comparison.
