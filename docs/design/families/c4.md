# C4 architecture diagrams

The five legacy Mermaid headers—`C4Context`, `C4Container`, `C4Component`,
`C4Dynamic` and `C4Deployment`—share one native C4 family. The language baseline
is now `mermaid@12.2.0`, source commit
`1fb7869866dd619168d840291c9c54b4f129758b`. The initial implementation used
`mermaid@11.16.1`, tag commit `7ecca0cd7f1658ef74f4e7e91f925724ef403bbf`;
that earlier pin remains historical evidence.
[C4's domain model](https://c4model.com/) supplies the visual contract:
people and typed software elements, recursive responsibility/deployment
boundaries, and individually identifiable interactions.

The implementation starts from Agentic main
`a87ec8612c3df98a5b9e8f52ac0e35814b02c523` (17 October 2026), including prepared
text, source identity, compound terminal layout and marker fixes. These are
source capabilities; publication and deployment require their own release.

The latest 18 October rebase review binds candidate
`8cad259fdcb8e0117531bf1d33585d9c79ae89f2` to Agentic main
`b1a613a47ee50d99f59dbf24bdf499f5a68ae2df`, including Class PR #410 and
documentation PR #414. All 34 imported
reference files, including 33 syntax pages, match that main revision byte for
byte. The five C4 Mermaid fences are unchanged; their documented visibility
limitations still apply. The full reference corpus and focused C4 geometry,
presentation, rendering and public-contract checks pass with Mermaid 12.2.0
installed, alongside the combined Section B golden and 297-diagram layout
baseline. The four Class panels retain main's exact pixels while C4 keeps its
reviewed panels. This does not rewrite the dated peer or build measurements below.
Main now supplies the shared Scene admission reuse, SVG assembly and schema
caching work; the earlier `56e46324` performance comparison remains evidence
for its recorded candidate and baseline, not this later rebase.

## Semantics and projections

| Construct | Native behavior and limits |
| --- | --- |
| Elements | All twenty official macros: Person/Person_Ext plus System, Container and Component with plain, Db, Queue and external variants. Role, shape and external status remain independent. Type, technology and description appear as text; distinctions survive without color. |
| Boundaries | Boundary, Enterprise_Boundary, System_Boundary, Container_Boundary, Deployment_Node, Node, Node_L and Node_R retain recursive typed parents. Node_L/R align their frame text. Empty frames remain visible and receive a Mermaid portability warning. |
| Interactions | Rel, BiRel, all directional aliases, Rel_Back and RelIndex retain every occurrence, including parallel, reciprocal, self and boundary interactions. Back retains the authored endpoints separately from the effective arrow. BiRel has two endpoint markers. |
| Dynamic order | Explicit RelIndex values are preserved and displayed. Other C4Dynamic relationships display their one-based source ordinal. Explicit index and lexical order remain separate facts. Mermaid's repeated-pair overwrite and discarded explicit indices are deliberately avoided. |
| Layout | Row counts and compatible directional hints affect placement. Conflicting hints receive diagnostics. Optional `c4.maxWidth` reflows measured pixel boxes; `c4.compact` selects tighter independently measured pixel/cell spacing. Minimum readable geometry and explicit constraints take precedence over a width budget and report `LAYOUT_LIMIT_EXCEEDED`. Identical source/options remain deterministic. |
| Text | Literal labels retain technology, descriptions, punctuation and Unicode. Authored `<br/>` breaks are interpreted before entity decoding, so encoded tag-like text remains literal. Each output measures and emits the same prepared text block. |
| Styles | Element/boundary colors and relationship colors are admitted through the shared safe-color contract. Explicit shape selection (person, rectangle/box, database/db/cylinder, queue/pipe) uses one family helper for both outputs; authored role, macro shape and external status remain separate. Pair-scoped UpdateRelStyle applies to every matching authored pair. Finite relationship label offsets remain graphical settings. Unsupported visual effects are preserved and diagnosed. |
| Tags and links | Tags and authored/effective links remain typed metadata. Supported tag styles cascade before explicit styles. Links use existing inert action metadata and URL admission; renderers never execute them or fetch remote resources. |
| Unknown syntax | Untouched source survives byte for byte. Unknown native interpretation blocks partial rendering; uncertain alias references prevent unsafe identity edits. Malformed unbalanced source falls back losslessly and fails strict rendering. |

Deployment type and description appear in the frame header. Person figures,
database rims and queue endcaps provide shape cues alongside textual types.
The terminal path draws relationships between owned cards/frames using the
existing compositor, ports, markers and routes. It does not derive a diagram
from SVG or a list of relationships beneath disconnected boxes.

## Reflow, style and navigation

```ts
renderMermaidSVG(source, {
  style: 'excalidraw',
  mermaidConfig: { c4: { maxWidth: 720, compact: true, typeLegend: false } },
})
```

The width budget affects packing and prepared wrapping before routing. It does
not shrink fonts or rescale a finished diagram. Pixel `maxWidth` is distinct
from terminal `targetWidth`; terminals keep their own measured cells and can
refuse impossible geometry. `compact` changes defaults, while explicit authored
spacing and style padding retain precedence.

Automatic semantic type legends are enabled by default when several types are
present. Set `typeLegend: false` to omit that chrome; the cards retain their
type text and silhouettes. Explicit `SHOW_LEGEND` remains authoritative and
includes authored tag definitions. Legend swatches use effective shapes and
configured/authored colors, then the shared legend role and palette fallbacks.
Node, group, edge and legend paint travel through the existing Scene and style
backends. No color is required to distinguish person, external, database or
queue semantics.

The editor's Boundary selector fits an authored frame using existing zoom/pan.
It leaves the complete canonical artifact intact. SVG/PNG exports include the
whole diagram; Save Mermaid source exports the exact editor text. Selecting a
boundary never deletes context, changes interaction identities or renumbers an
explicit dynamic index. The selector is available only for a current verified
graphical C4 preview.

Final measured label halos and marker envelopes are checked after authored
offsets. Unresolved `C4_LABEL_COLLISION` or `C4_ARROW_OCCLUDED` becomes the
geometric error `CONTENT_OCCLUDED` and fails verification. Source and metadata
retention alone cannot make hidden content readable. These checks cover the
measured geometry, not every font raster, styled stroke or perceptual ambiguity.

The five pinned upstream C4 examples also encounter these visibility limits.
Their authored label offsets remain authoritative and can place halos over
cards, arrows or deployment frames; some route/halo crossings remain even
without offsets. The official-fence corpus records `VerifyError` for those
examples while still requiring parsing, rendering and structural count
preservation. Dense and constrained layouts can require source adjustments.

## Agent editing

```ts
import {
  asC4, buildMermaid, mutate, parseRegisteredMermaid,
  serializeMermaid, verifyMermaid,
} from 'agentic-mermaid/agent'

const built = buildMermaid('c4', [
  { kind: 'add_boundary', boundary: { id: 'shop', label: 'Shop', kind: 'system' } },
  { kind: 'add_element', element: {
    id: 'api', label: 'Order API', kind: 'container', technology: 'TypeScript', parentId: 'shop',
  } },
  { kind: 'add_element', element: {
    id: 'db', label: 'Orders', kind: 'container', shape: 'database', technology: 'PostgreSQL', parentId: 'shop',
  } },
  { kind: 'add_relationship', relationship: { from: 'api', to: 'db', label: 'Stores', technology: 'SQL' } },
], { c4Variant: 'C4Container' })
if (!built.ok) throw new Error(built.error.message)
const checked = verifyMermaid(built.value)
if (!checked.ok) throw new Error(JSON.stringify(checked.warnings))
const source = serializeMermaid(built.value)
const parsed = parseRegisteredMermaid(source)
if (!parsed.ok) throw new Error('Invalid source')
const diagram = asC4(parsed.value)
if (!diagram) throw new Error('C4 source is not structured')
const interaction = diagram.body.relationships[0]!
const updated = mutate(diagram, {
  kind: 'update_relationship', id: interaction.id, changes: { label: 'Stores accepted orders' },
})
if (!updated.ok) throw new Error(updated.error.message)
```

`describeOps('c4')` owns the complete operation schema. Operations add, update,
rename, reparent and remove elements/boundaries; select individual interactions;
and manage title, dialect and supported directives. Removing referenced
objects requires explicit cascade. Reparenting rejects cycles. Failed edits
leave the original diagram intact.

Aliases are source identities before display sanitation. The family allocates
interaction IDs after reserving every authored alias, including names such as
`c4-rel-1`. These are **selectors in the current artifact**: standard Mermaid
C4 cannot encode arbitrary durable interaction IDs. Adding/removing declarations
or interactions can reallocate them. Read IDs from the successful edit result
before the next operation. That result, serialized source, reparsed body,
semantic facts and output metadata agree. Displayed dynamic indices are not IDs.

Untouched statements, comments, CRLF and wrapper bytes remain preserved. Editing
one modeled declaration rewrites its own statement, with Mermaid entity escapes
rather than JavaScript backslash quoting. Rename updates typed parent, endpoint,
style and layout references; it never rewrites arbitrary quoted prose.

## Portability and honest losses

The reader accepts clear extensions with `UNSUPPORTED_SYNTAX` warnings:
multiline arguments, standalone direction, empty boundaries, and recognized
fork tag/link/legend/layout directives. Unknown statements or duplicate/conflicting
arguments cannot produce an apparently complete native render. An unchanged
source-preserved extension is not a promise that Mermaid accepts it. Typed
new directives stay within the portable supported Update* macros.

The documented positional RelIndex metadata slots conflict with Mermaid
11.16's implementation. Agentic retains the documented tags/link slots and
warns about ambiguous positional metadata. Prefer named `$tags` and `$link`.

Sprites remain metadata with an offline text fallback; no remote sprite is
fetched. Unsupported shadow, unknown shape (including rounded/component) and sprite effects are named
rather than silently advertised as native paint. Per-type font-family settings
are not claimed as consumed where the shared Scene text contract cannot carry
them. Terminal typography and graphical fill/offset/spacing settings receive
projection diagnostics when cells cannot express their effect. Narrow terminal
widths can explicitly refuse a layout; success at one width proves that width.

There is no new cancellation API on the synchronous parser. Its forward scanner
advances across skipped whitespace/comments and balanced unknown blocks, or
fails on malformed delimiters. Adversarial tests cover long skipped input and
malformed tails. Existing Code Mode execution limits remain the cancellation
boundary; this is not a claim about a cancellable standalone lexer.

## Reuse and validation

C4 owns parsing, the semantic identity plan, hierarchical placement and physical
port choices. Shared prepared text, typed Scene parts, graphical route repair
and certification, URL/color admission, and terminal card/frame/port/route
primitives retain their existing owners. No runtime dependency was added.

The C4 tests exercise semantic closure after edits, authored whitespace and
generated-looking identities, independent repeated interactions, physical
endpoints and owned terminal ink. Public transport tests execute Code Mode,
CLI SVG/ASCII, current-body rendering, offline PNG and action-region metadata.
The existing official-fence corpus and family citizenship/style/browser tests
include C4. Parser acceptance and PNG signatures alone do not prove geometry.

The final lazy build measures 4,460 bytes gzip for the four-request initial
loader. C4's complete first-render closure is 227,905 bytes gzip in 25 requests,
including shared SVG code; it excludes ELK. The initial paired build against
the pinned baseline used the same installed toolchain and found changes to
shared chunk boundaries: Flowchart/State/ER gain two requests and Pie gains one.
Their request budgets reflect that tradeoff. Existing byte budgets are retained
except 500-byte gzip allowances for XY and GitGraph; final GitGraph measures
184,637 bytes against its 185,000-byte cap after the shared configuration
diagnostics were added. These are download measurements, not rendering speed
benchmarks or evidence that a live site deploys this build.

The website has separate route budgets. Its existing synchronous editor bundles
all native graphical/terminal families and verification; the final CI capture
is 3,590,858 raw / 1,089,260 gzip / 859,297 Brotli bytes in two requests. Its
ceilings are now 3,610,000 / 1,095,000 / 865,000 bytes. The examples route's
build-time C4 SVG/card brings it to 418,997 raw bytes against a 425,000-byte cap;
its compressed ceilings are unchanged. These intended feature costs remain
subject to the separate per-PR payload-delta review.
