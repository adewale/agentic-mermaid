# PR449: academic methods, representation changes, and falsifiable experiments

Research note, 22 October 2026. This is exploration, not an implementation or a new benchmark result. Read against the repository's `docs/design/system/layout-qualification.md` and `layout-community-comparison.md`. Code observations refer to PR head `9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9`; the qualified renderer remains frozen at `e9db0dbe8bac597f6db7198ecfe388f5cfbbbf01` (`agentic-layered@22`). No renderer code was changed, benchmarks run, or third-party implementation copied for this note.

## Recommendation

First repair the transfer of constraints and geometry between the generic engine and family adapters. Architecture optimizes placement before routing its authored port sides; ER reserves generic label space and then independently positions its final labels. Adding another general search pass would optimize an incomplete model and repeat work. Next, test small, family-specific changes against final painted geometry. Only then replace expensive representations identified by profiles, such as long-edge expansion or visibility-grid states.

There is no basis for claiming that we have beaten ELK on every aspect. The qualification already shows aggregate crossing, area, route-length, parallel-span and opposing-span advantages alongside individual failures: Architecture contributes two source cases with more crossings; ER case 40 contributes sixteen foreign-shaft label conflicts; bends are worse on 25 source and 268 generated cases; area is worse on 34 source and 191 generated cases. Six uncached cyclic cases allocate 1.485–2.096 times ELK, and cyclic-labelled-15 and -18-cuts exceed the 1.5-times per-case time ceiling. These observations motivate experiments; literature does not close these gaps by citation.

## Evidence ladder

* **Measured here previously:** only results in the qualification/comparison documents. The two engines' paired corpus results, retained failures, cache policies, and A/A controls are the baseline.
* **Observed in source here:** the adapter and solver behavior below. A plausible causal mechanism is not a measured attribution.
* **Established in cited work:** a result under the paper's model and experimental population. A route optimum for fixed rectangular obstacles is not a global diagram optimum.
* **Proposed here:** a mechanism and a rejection test. Every expected improvement below remains unmeasured.

## Concrete source findings

### Architecture: final routes are missing from the ordering objective

[`src/architecture/layout.ts`](https://github.com/adewale/agentic-mermaid/blob/9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9/src/architecture/layout.ts#L93) correctly disables generic route-preference comparison: temporary graph routes do not describe the side-constrained final routes. The adapter already derives deterministic sibling-order constraints from authored endpoint faces around line 446. This is therefore a refinement of an existing port-aware mechanism, not a proposal to add ports from scratch.

At [`routeArchitectureEdge`](https://github.com/adewale/agentic-mermaid/blob/9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9/src/architecture/layout.ts#L814), an obstacle-clear direct middle is accepted; otherwise a Manhattan obstacle router is tried. The function receives node/frame obstacles but not previously routed edges or a joint channel order. Thus a clear individual route need not be good for the final crossing count. Existing same-scope placement fallback retains the original authored relationships for later routing, but dropped placement constraints are not evidence that a final crossing is unavoidable.

**Experiment A:** trace both extra-crossing cases from sibling constraints through ordering, frame repair, final anchors, channel choices, and crossing witnesses. Hold placement fixed and enumerate a small deterministic set of final route alternatives; separately hold routing fixed and compare a bounded set of legal sibling orders. This distinguishes placement failure from routing failure. For tiny cases, an offline exhaustive order/channel oracle can bound the heuristic gap without adding a production MILP dependency. Reject an approach that simply moves the crossing to another pair, reverses an authored side, changes an endpoint, crosses a card/frame, or increases another hard quality failure. Target: remove both excess-crossing cases and preserve the 634 paired generated crossing non-regressions. A different route order may expose unavoidable crossings under fixed placement; that is a useful diagnosis, not failure to search long enough.

**Subtraction A:** introduce a placement-only internal contract for this adapter, if profiling confirms it avoids generic routes/label work that are immediately replaced. Preserve the constraints contributed by cross-scope relationships even when their routes are deferred. Removing edges from a temporary representation is only valid when their placement semantics remain represented. Final routes and certification still run.

### ER: label reservations and final labels are separate systems

[`src/er/layout.ts`](https://github.com/adewale/agentic-mermaid/blob/9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9/src/er/layout.ts#L777) measures relationship labels and sends padded sizes to native placement. Its return around line 795 keeps the routes' `points` and drops their `labelPosition`. [`separateRelationshipLabels`](https://github.com/adewale/agentic-mermaid/blob/9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9/src/er/renderer.ts#L517) subsequently searches against entity/header boxes, endpoint marker zones, and prior labels. Foreign relationship shafts are absent from that obstacle set. This is a concrete mismatch; it does not establish that preserving every generic label position will solve case 40, because the adapter can alter routes and group geometry.

**Experiment B:** propagate optional label position/reservation alongside each route, applying the same translation operations, and invalidate/recompute it whenever repairs change its segment. Include foreign shaft envelopes in the final label feasibility test. First compare “reuse still-valid reservation” and “shaft-aware interval placement” independently; then test bounded one-axis space opening only where neither can find a clear interval. The experiment must retain eighteen-pixel marker exclusion zones, entity and frame headers, orthogonality, label ownership, and terminal normals. Target: ER case 40's sixteen conflicts become zero without increasing other label/paint failures. Failure modes include dense routes with no usable segment, compaction that moves a label off its owning shaft, and resolving one conflict by creating a marker collision. Do not hide these as a midpoint fallback success.

**Subtraction B:** one authoritative label reservation/result protocol replaces padding once and placing independently later. This may reduce duplicate work; measure allocation rather than assuming it.

### Bends and area: the current selector deliberately allows tradeoffs

[`refineOwnedLayoutCandidate`](https://github.com/adewale/agentic-mermaid/blob/9ffd5369cbc9676dbeb07c06abf3fc33c76bd5b9/src/layout/agentic-producer-core.ts#L210) compares a bounded number of certified candidates lexicographically by labels, opposing overlaps, parallel overlaps, crossings, bends, then area. A crossing reduction can therefore accept arbitrarily worse bends/area within the other limits. It also returns early when the first candidate has zero crossings, so this refinement cannot help zero-crossing drawings whose only problem is excessive bends or area. That behavior may be a deliberate policy; it should be visible in reporting.

**Experiment C:** attribute every accepted candidate to the first improving objective and record all other deltas. On the same candidates, compare the present selector with a Pareto guard and a declared per-family bend/area budget. Also test a cheap collinear/detour simplifier with fixed endpoints and final paint checks before adding another layout candidate. Reject a weighted scalar that conceals the tradeoff. Test whether the policy removes regressions or merely gives back crossing wins. Exact all-metric domination may not exist; publish the frontier rather than promise it. Reject simplification that removes required marker clearance, label-support segments, port leads, or boundary exits.

### Cycles: shrink representations before expanding search

`agentic-layered-core.ts` already uses Fenwick-tree crossing counts, bounded candidate exploration, and explicit expanded-graph/work limits. “Add Fenwick counting” would not be new work. It still expands long edges into per-rank helper vertices; cycle alternatives and compact private ranks can rebuild geometry. The generic selector can certify the first candidate, certify alternatives, and certify its chosen result again; some of this may be contractually required. Source inspection alone cannot identify the dominant allocation.

**Experiment D:** count ranks, helper vertices, arcs, route-grid vertices, candidate builds, full geometry conversions, and certification passes per input, and join those counts to allocation profiles. If expansion correlates with the six cyclic allocation regressions, prototype sparse long-edge chains behind an internal flag. If route states dominate, test the one-bend visibility representation instead. If repeated reconstruction dominates, reuse immutable topology/measured dimensions and candidate-local scratch arrays with explicit ownership. Preserve all label ranks, original arrows, duplicate-edge identity and proof inputs. Reject changed work caps, disappearing declines, stale scratch state on edits, unbounded caches, or a faster warm result with worse uncached behavior. Target both uncached outliers below 1.5 times ELK and all six allocation regressions reduced, without sacrificing the quality gates. Run fresh A/A controls; do not divide noisy timings by A/A as a correction.

### Hints and ancestor endpoints: support constraints incrementally

The generic native producer currently explicitly declines active rank/adjacent/short-edge hints. Bounded cross-scope frame terminals already work; ancestor-container endpoints are a separate unsolved capability. Flattening or silently replacing these with descendants changes meaning.

**Experiment E:** admit one constraint class at a time. Start with feasible same-rank constraints in an acyclic flat graph: build equality components, derive rank inequalities, detect contradiction before geometry, and retain a typed decline on infeasibility. Then test adjacency with an explicitly defined meaning rather than treating it as an aesthetic suggestion. Model-order tie-breaks are suitable only inside the remaining legal degrees of freedom. For ancestor terminals, keep boundary identity as a terminal with explicit allowed boundary/exit constraints; add nested adversarial cases before expanding admission. Test edit/hint add/remove cycles for deterministic SVG restoration and unaffected-node movement. Reject any “support” that ignores a hint, conflates node/frame IDs, silently changes an endpoint, or expands admission without final checks. A narrow native domain with honest fallback is preferable until these contracts exist.

## What can be learned from pinned community implementations

* [Pele layered solver](https://github.com/obsidianmd/pele/blob/1dd58b7ebb0ec654fa7dc4304d50cf8fd3a65d7b/src/layout/layered.ts) states an explicit priority order: route distinction and label/node clearance before crossings, then simple/short routes and later compactness. Borrow the transparency of the contract; it does not establish that its outputs satisfy our semantics or metrics. Its [compound implementation](https://github.com/obsidianmd/pele/blob/1dd58b7ebb0ec654fa7dc4304d50cf8fd3a65d7b/src/layout/compound.ts) also illustrates boundary-port modeling, but effective-endpoint projection is not permission for us to substitute authored endpoints.
* [Ondine compound source](https://github.com/wevm/ondine/blob/0b589ec34481856b4153526f10a0a35558a201a8/crates/compiler/src/layout/compound.rs) explicitly ports Pele. Similar behavior is related implementation evidence, not independent algorithm validation.
* [Zombie's simple-layout decision](https://github.com/dfadler/zombie-mermaid/blob/ae30b804c70d89b072e3d20265d0d0c752a9f11f/docs/decisions/simple-layout-1685.md) demonstrates a deliberately narrow Sugiyama implementation and fixed small passes. It is a useful subtraction experiment for flat flowcharts. Its accepted limitations, including ignored subgraph directions and some back-edge collisions, cannot be accepted merely to reproduce its speed.

No peer source or literature result supports extending the generic engine to every Mermaid family. Sequence, Gantt, Pie, and other specialized grammars require separate evidence; current shared-pipeline overhead can exist even when this solver is unused. Conversely, shrinking the native family set would avoid some failures but lose achieved coverage. Route by an explicit constraint contract and measured per-family cost/quality, not a family-count target.

## Evaluation plan and order

1. Preserve the current source and generated qualification as development data, including all failures, timeouts and unverified paint. Declare fresh seeds/adversarial holdouts before tuning.
2. Instrument phase contracts and candidate deltas first. Rendered SVG/scene geometry is the common quality artifact; internal rank crossing counts are diagnostic only.
3. Address ER reservation loss/shaft omission and diagnose Architecture's two crossing witnesses. These are focused, falsifiable changes with direct user-visible benefit.
4. Compare simple bend/area policies on the same candidate set. Report crossing/bend/area tradeoffs per case and family, not only totals.
5. Choose sparse normalization, sparse visibility or reconstruction reuse only after the allocation attribution. Change one representation at a time and keep the old path for controlled comparison.
6. Expand hints/ancestor admission through small explicit contracts; otherwise retain strict decline and ELK fallback. Keep ELK as default until the separate default-switch gates pass.

Retain original endpoints and directions, authored port sides, layout hints, group membership, labels, marker clearances, typed declines, deterministic output, existing work budgets, bundle caps, and final geometry/paint certification. A failed convex-separation proof remains unknown. Removing uncertainty, raising caps, increasing deadlines, ignoring losing cases, or using the same corpus to tune and declare universal superiority is not an improvement.

Expected deliverables from these experiments are fewer adapter mismatches, an attributed cost profile, and a documented quality frontier. None of the proposed effects in this note has been measured yet.
