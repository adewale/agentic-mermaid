## Complete controlled cost result

The separately declared method uses pinned Node24.19.0, all 75 original H27+D48 inputs, both cache policies, six blocks and independent repeats of accepted native, d74 native and same-d74 stock ELK. Each process performs one complete warm pass and two timed passes: 225 calls, comprising 5,400 warm and 10,800 timed calls across the campaign. The earlier 450-call-per-process campaign remains failed; this explicit finite workload does not repair it or establish steady state.

All 72 processes finish under the original 120-second worker and 2,700-second policy limits. Complete SVG UTF-8 and receipt JSON are consumed in the original timing envelope. Cold Python/fork/Node memory ownership, Node SELF peaks, output caps, raw journals, oracle matching and cleanup pass. The parent waits without recurring filesystem scans while its child runs. There is no forced GC, profiling, A/A division, selected-round exclusion or time correction.

The frozen assessment ran once. Independent raw readback verifies all 16,200 calls and recomputes the original endpoints and controls. **No timing or RSS benefit is qualified.** The source candidate's declared uncached tail-benefit objective remains unqualified.

## Feedback, correctness and remaining work

The Frankenmermaid feedback informed ordered incidence/scratch subtraction and a construction-aware node census. The d74 source candidate preserves its enrolled complete outputs and delivery, but has no qualified cost improvement and is not adopted. The separate deferred route-snapshot prototype passes owning tests, direct route comparisons and delivery; its runtime benefit is also unqualified.

The named-provider/error-identity compatibility prototype passes isolated Node and browser checks. Joint integration with #433's canonical YAML/replay owner remains outstanding; there is no second YAML/security implementation, copied #471 production trial, raised retry count alone or combined percentage claim. The remaining production qualification dependency is preserved.

For the tested application inputs, the pruned ELK implementation matches the qualified ELK outputs across Node, lazy browser and IIFE boundaries. Native and ELK legitimately choose different geometry. This does not prove every input's paint, route quality or arbitrary library API correct. Historical native long-route, bend, Architecture and edit-stability deficits remain; no new quality victory follows from exact subtraction.

The evidence supports smaller selected delivery and a viable private compiler specialization. Reliable native timing/RSS qualification, maintained production packaging, joint provider integration and the remaining per-input quality losses are still open. ELK remains the default and the PR remains draft.
