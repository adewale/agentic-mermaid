The first implementation unit is the neutral role-aware boundary, with existing
backends delegated unchanged. Do not rewrite every family or add a backend registry
before that unit demonstrates value. Kernel work and an independently shippable
shared repair may proceed separately; shared improvements do not count as Trinity
closing its relative gap with ELK.

For each real change: reproduce the loss, locate its first responsible stage,
test the smallest causal intervention, qualify the affected contracts, then commit
and push a coherent milestone with recoverable evidence. Broaden checks at coherent
milestones or when failures justify it. Preserve all enrolled failures and costs;
unchanged comparisons are validation. No new assistant-created acceptance gates.

## Starting position

Trinity has no implementation or measured results. The neutral contract extraction
preserves existing ELK/Native runtime behavior. At `f55a8f8ec`, Native's known
contacts and Sparse32 proof exhaustion remain. ER256 delivery is already repaired
through both backends; option validation is already a leaf module. Neither is an
unfinished task to repeat. Runtime CI remains failed; this design makes no readiness
claim. Latest exact-head status belongs in the PR, not an expanding plan history.

The specification's metric table links the published Trident baseline and focused
Class128 supplement. Those retain partial fidelity, unknown ink, mixed cached
costs and growing retention. Pele source is recovered; a comparable Pele runtime /
actual-ink ranking remains unexecuted. No general replacement claim follows.
