# PR449: achievements, ELK comparison, and remaining work

**We have not matched or beaten ELK on every aspect.** The native engine has demonstrated useful quality, memory and delivery advantages on named populations. Cyclic Flowcharts, prospective Architecture quality, edit stability and complete performance qualification still expose substantial gaps. Several plausible optimizations failed their declared tests; none earns production credit merely by preserving output or reducing an internal counter.

There are two different source states throughout this report:

- **Historical accepted runtime 26:** source `3258d80c`, with the later evidence/reporting base `adb8e7e9`. The quality and memory numbers below belong to those frozen artifacts.
- **Current integration:** source `968b85564ec0745613abed1b114e5f729d67ca84`, rebased over main `861375d33807a668a0dd3674257840d027ea299e`, incorporates merged PRs 467 and 468 and the exact Architecture/cache-field delivery repair. Its canonical builds, types, lint, unchanged delivery caps, real-browser contracts and compiled Node 24 preservation checks pass. It has **no fresh post-rebase runtime-cost qualification**. Historical memory and timing results remain bound to their historical artifacts.

The rejected quality/cost experiments remain outside production. The final delivery repair is a separately validated combination; its failed standalone variants remain recorded. Original targets, failures and uncertainty are retained.

The same-stage filter needs an explicit correction in any summary: its `orderingScoreCalls` means **initial plus forward/backward barycenter `rememberOrder` calls**, not all ordering work. The broader core `crossingScore` counts fell only 3.4–19.1% across the six tails: 0/6 reached 20%. Later compact-block calls were unchanged. Even the broader counter excludes direct adjacent-swap reductions, private-chain DP and route scoring. Counter reductions cannot stand in for time or allocation measurements.

The failed phase trial has exploratory prototype/ELK ratios below 1 for some aggregate populations, but those do not qualify a speed claim: the baseline/A/A triples are incomplete, and all six observed uncached cyclic prototype/ELK medians remain above 1. Those prototype observations are never credited to accepted 26 or the current rebase.

Original five-pass timing failures remain failed. A separate one-prewarm/two-pass SVG protocol `@2` is implemented prospectively and under independent review, but is not yet finally frozen, declared or executed. It retains all 75 inputs: 75 prewarm calls plus 150 timed calls per worker, 225 total; two samples per input per round limit precision. The original UTF8 target contract remains unmet; no timing worker has qualified its product benefit. The workload also changes explicitly: `@1` materializes receipt JSON inside its metric window but creates the UTF8 receipt buffer outside; `@2` must include both full JSON and UTF8 materialization inside. Neither method can be relabelled as the other.

**Architecture: a useful repair with explicit tradeoffs**

The separate historical label-space dev 2 repairs all 16 previously hard-failed native/ELK development observations on the two fixed controls. There are 22 passed final paint certificates and two inherited unverified ELK certificates; those two retain accepted 26's exact SVG, layouts and receipts. All eight SVG undos and eight layout undos are exact. No crossing, bend, shared-ink, authored-contact or hard-route regression appears in these controls.

It is not a Pareto improvement: 22/24 observations grow length and area, with maximum increases 11.13% and 13.27%. All 16 measured edit transitions increase unaffected aligned normalized mean motion, maximum +0.09235. These fit the prospectively explicit 3× length/2.5× area/+0.5 motion concessions; they do not establish a strict compactness or stability win. The representative labelled SVG golden still fails because measured separation grows height 280→294.55; it was deliberately left unchanged. Themed golden and 180 other tests, types, lint and Node/DTS pass.

The fresh 128 cohort remains ungenerated. No fresh 128, broad retained 64/80 or cost campaign was run for dev 2, and it is not a repair qualified on the newly rebased source. Root review must decide whether these concessions fit the product goal before any port or golden update.

**What community practice and literature contributed**

The community catalog contains 83 related projects, including forks, ports and bindings; it is not 83 independent algorithms. A frozen 06:53 UTC audit read all ten then-open issues, seven then-open PRs and 42 returned discussion entries, with independent PR timeline checks. That is exhaustive only for that retrievable inventory, not closed discussions or the global Mermaid community. Later ownership refreshes record PRs 467/468 merged into main. The recurring guidance is final-family route quality, actual dependency identity, private cache ownership and preserving fallback/proof uncertainty; it is not a measured endorsement of native superiority. Inspected implementations supplied concrete ideas: Pele's phase priorities and zero lower-bound stopping; Merman's score-only guard and runtime ownership; Dagre/ELK ranking, ordering and routing separation; explicit label space and authored-port contracts. Historical community timings against our runtime 22 favored Pele strongly. That benchmark used a different Pele version from the inspected source; differing versions, workloads and retained proof/receipt obligations prevent a current 26 parity claim.

The academic ideas have practical limits in this pipeline. Gansner-style layered ranking and parallel-constraint reduction preserve a completed rank objective, but finite shared budgets can change which layout candidate exists; weighted ranking demonstrated that distinction. Orthogonal-routing work by [Wybrow and colleagues](https://users.monash.edu/~mwybrow/papers/wybrow-gd-2009.pdf) motivates corridor ownership, while our authored sides, rounded geometry, groups and final marker proof still require validation. [Brent's cycle-detection work](https://doi.org/10.1007/BF01933190) supplies a deterministic-recurrence precedent, not a graph-quality or product-performance theorem. Mental-map and model-order work motivates stable discrete choices; the 48 worse fresh Architecture motion transitions show that this goal remains open.

We also considered fewer native families and simpler shipping contracts. Flowchart-only retains all six expensive cyclic cases. An acyclic-only contract leaves the cyclic goal unresolved and requires explicit typed declines/fallback. Shared solver/proof closures mean removing an adapter does not imply a proportional byte saving. No new family restriction, expanded family portfolio or default-engine change is approved or counted as an achievement here.

**Current integration: what is now verified**

The final canonical source is `968b85564ec0745613abed1b114e5f729d67ca84`. Standard Node ESM, IIFE, lazy-browser and declaration builds, core/repository types and scoped lint pass. The actual browser run passes 55 tests with 1,035 assertions, including Firefox/WebKit public and lazy-ESM smoke checks. This is local validation; it does not assert a newly green remote required-CI run.

Actual pinned Node 24.19 performs 696 successful captures across eight fresh artifact/backend/cache workers. All 348 complete pairs match historical accepted `3258d80c` exactly on the fixed 87 inputs (H27+DAG48+12 Unicode controls), including full SVG, receipts and layout results; all standard within-arm V8 round-trips are exact under the declared deep-strict value comparison. An offline supplement checks all 348 stored pairs and finds no own enumerable-key-order differences across 300,624 object pairs. These captured values contain zero Map/Set instances, so this corpus provides no collection-order coverage; swapped-Map/Set negative controls establish only the checker’s behavior. Cross-arm V8 hashes are equal for 232 pairs and unequal for 116; their residual binary encoding or alias-representation cause is undiagnosed, and unequal serialization bytes alone are not treated as a product-value defect. The actual Node87 jobs set scene assertions to literal `0`; the audited built-in assertion branch is enabled only by `1`, so `0` and unset take the same branch. The separate diagnostic-admission jobs use unset. These are preservation observations, not fresh ELK quality rankings or cost measurements.

The separate compiled cache smoke also passes its public semantic assertions. Its initial persistence protocol failed because V8 changed 34 ASCII null-prototype objects into ordinary Objects; a conservative follow-up envelope rejected six legitimate lazy getters. Both protocol failures remain retained. A separately predeclared lossless envelope `v2` supports getter-produced values and restores null prototypes through a graph-ID sidecar, passing strict value equality, topology/own-key/alias witnesses and ten negative controls. Getter-function/property-descriptor identity is outside this value proof. Actual private hits are established by the separate source sabotage tests, because public smoke does not expose private counters.

The final delivery repair reuses Architecture metadata and actual positioned-object lookups and changes internal cache fields to JS private fields. Its isolated owning checks pass 84 tests; final-root cache, ELK/Sequence and probe checks pass 74, 11 and 9 tests respectively. These groups have their own scopes and are not added into a unique-test total. Geometry, alignment mutation ownership, map insertion/iteration order, cache weighting/eviction/cloning and fail-closed diagnostic anchors are preserved.

All 23 unchanged delivery caps pass. Architecture's default closure is 573,975 bytes Brotli, only 25 bytes below its 574,000 cap, versus the retained initial 574,137-byte failure. The initial closure remains four requests and 4,932 bytes Brotli. The narrow margin is a maintenance risk; no budget was increased. No runtime speed, allocated-byte or retained-memory win is inferred from source subtraction or compression.
