# Owned backend qualification: implementation and evidence

The target is quality parity with ELK plus lower public-workflow time, memory,
and browser transfer cost. Supporting selection alone does not close that target.
ELK remains the default and supported fallback. No default change is proposed.

## Research applied

The starting inventory is [Mermaid Community](../../mermaid-community.json).
Project descriptions and ancestry are leads, not benchmark evidence. Sources
were inspected at these revisions; no third-party layout code was copied.

## Protocol and populations declared before qualification

- Freeze the implementation commit before measuring. The starting package is
  `de376e4c0859cf3308ce011c1c4b95e6738ef069`; preserve its adverse observations.
- Retain the complete source/fixture graph population and scaling workloads.
  Publish distinct sources and occurrences separately. All unsupported cases,
  paint rejections, and missing measurements stay enrolled.
- Retain all 512 prior generated Flowcharts as development evidence. The fresh
  counter-generator holdout is `sha256-counter-v1`, seeds **128–191**, 64 cases.
  Any solver tuning based on it makes it development data immediately.
- Inspect a fixed visual sample across all six graph families, including the
  frame-endpoint corpus Flowchart and Architecture source/group/port cases.
- Run all declared edit sequences in `eval/layout-compare/edit-sequences.ts`
  with ELK, strict native, and native with fallback, under both startup cache
  policies. Retain unsupported hint transitions and undo outcomes.
- Run the full 27-input canary, three rounds and 25 consumed repetitions, in
  both cache regimes with the unchanged 480-second shared bound. Include all
  three selections and the same-artifact ELK A/A arm. Timing runs are serial
  and do not compete with builds, tests, or report generation.
- The new opt-in `--layout-reference batched` protocol imports once per fresh
  arm/round and interleaves all enrolled inputs within each repetition. It
  changes cache pressure from legacy isolated-case scheduling and must be
  reported separately. Every arm gets all cases; memory remains independently
  paired by exact successful population. No retries, deadline increases,
  smaller populations, or A/A normalization rescue a failed campaign.
- Report raw visible polyline bends, length, canvas area, measured label
  conflicts, shared spans, paint uncertainty, and measurement coverage. A
  support gain is an improvement, a lost render is a regression, and a missing
  population member remains adverse. Improvements cannot mask worsening metrics.
- Rebuild Node/declarations/IIFE/lazy artifacts. Check actual request graphs,
  unchanged payload caps, standalone workers, public surfaces, types, owning
  tests, and the existing default-geometry gate. Keep all historical evidence
  pinned to its measured revision.

## Remaining limits

Native layout hints, ambiguous overlapping node/frame identities, ancestor
container endpoints, work-limit declines, full preferred-port/symmetry scores,
and subjective readability still need explicit qualification or implementation.
The source inventory and seeded cohorts cannot prove universal dominance over
ELK. A dimension is only matched or beaten on the named measured population;
missing evidence is unproven. A successful CI artifact job is not qualification.

Results and reproduction commands will be appended after the declared campaign.
