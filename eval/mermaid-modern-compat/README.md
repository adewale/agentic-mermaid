# Modern Mermaid compatibility evaluation

This opt-in evaluation uses an independently installed Mermaid **12 or newer** as a parser/DB reference. It borrows Pele's combination of upstream documentation/spec corpora and seeded mutation testing. It does not compare layout or pixels against Mermaid.

The label census observes the current upstream docs, retained official fences,
legacy docs corpus, imported upstream benchmark and every registered family
example. Its expectations come from the independent reference's actual DB
getters; the benchmark's older `labelsContain` fixtures are not its oracle.

```sh
AM_MODERN_TARGET_DIR=/path/to/base bun eval/mermaid-modern-compat/run.ts \
  --mermaid-dir ../mermaid --reference-dir ../mermaid-reference --labels \
  --output /tmp/labels-base
bun eval/mermaid-modern-compat/run.ts \
  --mermaid-dir ../mermaid --reference-dir ../mermaid-reference --labels \
  --label-baseline /tmp/labels-base/label-census.json --output /tmp/labels-head
```

`label-census.json` retains every input's status, raw reference labels, model,
facts, describe tree, layout, SVG text, ASCII text and terminal-region text.
It reports text-presence candidates and base/head changes. Presence does not
establish identity, multiplicity, formatting, or equivalent drawings. Missing
text needs review: Markdown interpretation, documented generous-read choices,
intentional hidden labels, and source-preserved syntax can differ. The current
selected-field scope excludes Class/ER member signatures, sequence notes and
control captions, accessibility text, and Block space and composite identifiers.
XY point labels are included; visibility settings require semantic review.
Quality metrics expose aggregate label counts,
which are recorded separately rather than presented as per-label evidence.
Rejected inputs, unsupported families, and missing projections remain explicit
unavailable observations. Add `--specs` to include the broader parser-spec
literal harvest too.

The semantic gate checks independent label presence on model, facts, SVG,
ASCII and terminal metadata for every registry example. It also generates
Sequence edits combining boxes, activation, properties, unknown metadata and
punctuation, with explicit expected messages and independent reference actors.
That gate protects the named behavior; the broader census is a diagnostic.

`bun run eval:mermaid-grammar` runs the more detailed grammar assessment over
**every modern core family**, with **5,000 seeded mutations per family** by
default. It uses the same documentation/spec harvest as the rendering runner:

```sh
bun run eval:mermaid-grammar --fuzz 5000 --seed 7 --workers 4
```

The reference selects the family's real released Mermaid parser even when a
mutation corrupts the header. It observes Jison lexer tokens and `yy` calls;
Langium families expose their actual lexer and AST plus Mermaid's model-builder
calls; UseCase uses the pinned source lexer/CST and actual model commit. Source
paths, engine and observation availability are recorded per family. The model
snapshot comparison examines normalized values from observed stable getters
rather than element counts. A second parse of the original excludes volatile
observations. Parent fields are retained; cycles and non-JSON values are
explicitly normalized. Strings resembling generated IDs are not globally
rewritten: the GitGraph adapter normalizes only IDs proven autogenerated by
the actual authored AST. Ordered model calls and AST observations provide
additional evidence, not a full-fidelity guarantee.

The assessment distinguishes these observations and comparisons:

- **Native admission:** uses the public renderer's canonical request waist
  (including entity decoding, family routing and authored Class/Pie views),
  then invokes the actual family parser without layout or opaque fallback.
  Request-stage rejection is distinguished from parser-stage rejection.
  Admission uses default rendering/security options: a request-stage refusal
  (for example, raw `themeCSS`) is not a grammar rejection.
  The structured/opaque/preserved public envelope is reported
  separately. Unsupported families have no native acceptance verdict.
- **Native consumption and operations:** optional hooks inside all 17 native
  parsers record actual classified statements and semantic builder writes in
  execution order. Flowchart additionally exposes consumed compound node/link
  fragments; C4 records forward scanner chunks with physical UTF16 offsets and
  Unicode-code-point columns. Values are copied at the write site, before later mutation, and
  retain endpoint markers, logical IDs, memberships and parents. Coordinates
  state whether they refer to physical or normalized input. These are each
  native parser's own units, not invented Mermaid terminals or `yy` calls.
  Every observed native attempt is repeated without hooks; acceptance, error
  and complete native model must remain equal or the assessment fails.
- **Selected native semantics:** independent adapters for all 17 families
  compare declared semantic fields in actual native models against actual
  reference getters, builder calls or AST. They retain ordered values and
  parent relationships, normalize documented defaults and generated identities,
  and sort only unordered dictionaries. Each case includes the selected field
  names and first differing value. These comparisons are diagnostics; omitted
  styling, options or model fields cannot be inferred to match.
- **Selected ordered native operations:** independent adapters read actual
  native mutation events and actual reference call-time operands. They never
  read returned IR, getter snapshots or serialized text to construct a trace.
  Batch operands in State's `setRootDoc`, Sequence's `apply` and Radar's setters
  are expanded in their recorded order. Operations are never sorted. Every
  case declares its scope and counts selected source events, omitted event
  kinds/methods and omitted batch operands. For example, Flowchart compares
  links and class appends, while Timeline compares event writes because its
  period-construction order differs from the reference. Empty scoped traces
  provide no comparison evidence. These checks cover selected semantics,
  rather than equivalence of the engines' entire builder protocols.
  C4 compares declaration, boundary open/close and relationship calls, including
  their ordered operands. Variant, title, styles, tags, links, generated IDs and
  `RelIndex` are outside this operation scope. Native observations still retain
  those writes, including deferred styles. Mermaid commits the variant last,
  drops the `RelIndex` index and upserts repeated endpoint pairs in its getters;
  Agentic retains independent interactions. Ordered calls can therefore agree
  while the selected result models differ, as the reviewed repeated-pair case asserts.
- **Grammar round trip:** compares reference tokens, ordered model calls or
  AST, and stable model values for the original source against the reference
  parsing Agentic's structured serialization. Exact token/action differences
  are diagnostic: whitespace, declaration order and intentional normalization
  can change these streams without losing meaning.

Exact native-token/`yy` equality remains **unavailable**: the engines do not
share those interfaces. Both real streams are retained separately. No native
trace is reconstructed by re-lexing serialized output or walking returned IR.
The independent result projections are labelled as projections, not operation
traces. Unsupported families have unavailable native observations and semantics;
source-preserved or opaque acceptance never counts as native fidelity.

The runner writes ignored `output/grammar/summary.json`, one per-input JSONL
file per family, and up to 48 detailed counterexamples per family (up to eight
for each discrepancy category). Every case
records accept/reject outcomes and full-value comparison verdicts with the first
difference; every case retains native statements, operations, controls and its
selected native/reference semantic values. Detailed examples also retain
reference tokens, actions, AST and model snapshots.
The CI semantic command runs the reviewed preservation assertions, reduced
seeded writer regressions and ordered-operation assertions over all 17 canonical
native examples plus focused witnesses. Operation assertion reports retain
their exact scope and unmapped-method counts in `output/native-operations-gate.json`. Seeded writer
regressions publish `output/grammar-regressions-gate.json` and use actual default
Mermaid detection before and after serialization, with selected semantic fields
compared where meaningful. They cover reviewed failures, not all diagnostics.
Selected source-event counts include operands used as normalization context
(for example an earlier Mindmap node creation followed by its attachment).
They do not measure complete builder-protocol coverage.
Git identities use disjoint `{authored: string}` and `{generated: number}`
operands; an authored ID that resembles a generated placeholder remains
distinct from an automatic identity, including parent/head references.
Mutation IDs and parent origins make each input reproducible. Each family runs
the requested number of mutations of at most 4,000 characters; oversized
attempts are counted and replaced. Raw syntax disagreement is not a bug count
under the write-strict/read-generously policy.

A mutation inserts, deletes, duplicates or replaces text, drawing fragments from
the token images Mermaid's lexer produced on the family's corpus and from the
fixed lexer-boundary fragments in `grammar-fragments.ts`. A **silent read** is
an input the pinned grammar rejects that ours reads as the same family (native
parser or structured body) while `verifyMermaid` reports neither
`UNSUPPORTED_SYNTAX` nor a source refusal (`EMPTY_DIAGRAM`,
`UNRESOLVABLE_SCHEDULE`, `RENDER_FAILED`). The policy requires a generous read
to be announced, so these are the bug candidates. Every run counts them per
family in `summary.json` (`silentReads`), reduces the first eight of each
family by line and then code point, and prints each distinct reduction with
what ours read and Mermaid's error.
`--native-only` restricts a run to the families ours parses. Weekly discovery
(`.github/workflows/contract-discovery.yml`) has a ten-minute job cap and read-only
permissions. It uses `--fuzz 100 --corpus-limit 8 --candidates-per-family 2
--reduce-checks 8` with a recorded rolling seed. Structured contract candidates
are retained independently of silent-read examples and rechecked through the
existing triage oracle. Reduction preserves the same violated contract. Reports
are JSON/artifacts for human review; no issue is created or updated automatically.

Canonical CI calls the reusable semantic workflow for every PR/main revision,
and its success is required by `CI complete` and exact-commit release attestation.
It keeps the current pinned corpus replay, original assertions, and 100 mutations
per family at seed 7. Larger searches are explicit manual dispatches (default
5,000 mutations), rather than a second overlapping weekly schedule. Grammar
infrastructure failures fail the step; unsupported syntax and families remain
separate diagnostics. Use `--families flowchart,sequence`, `--docs-only`, `--fuzz`,
`--seed`, `--workers`, and `--output` for targeted reproductions. Omitting the
bounded discovery flags keeps the full corpus/manual diagnostic limits. The
independent reference directories use the environment variables below.

`bun run test:mermaid-modern` is the assertion-bearing companion. It requires
the Mermaid source commit from `docs/project/upstream-mermaid-policy.json`
and an independent matching installed reference, with no production dependency change. Defaults use sibling
`../mermaid` and `../mermaid-reference`; override them with
`MERMAID_UPSTREAM_DIR` and `MERMAID_REFERENCE_DIR`. The dedicated GitHub workflow
**Modern Mermaid semantic compatibility** installs those references and runs
the gate as a required canonical CI lane on every PR and main revision; it can
also be dispatched manually.
After the reviewed assertions, CI also records documentation coverage for
every core family and 100 mutations with seed 7. It retains the assertion report,
summary and per-case outcomes for seven days. These broader diagnostics do not
turn unsupported families or permissive input acceptance into CI failures.

The gate ports the repeated-subgraph member/first-title assertions from
`flowDb.spec.ts` and checks the `FlowDB.setClass` accumulation contract through
Agentic's public structured model, typed editing, positioned layout, SVG
identity and reference re-parsing. The actual reviewed upstream spec inputs
are extracted through the TypeScript AST without executing upstream tests.
Both sibling declarations and a redeclaration nested inside its own body are
covered, so canonicalization must flatten repeated identity without creating
self-containment or dropping members.
Two actual XYChart documentation sources assert writer validity and preservation
of titles, axes, data and per-point labels through reference semantic
projections. Missing nodes and lost class assignments fail even when a diagram
still renders and verifies. Results are saved to `output/semantic-gate.json`.

This is a selected port, not a claim to run every upstream spec. Mermaid's
renderer/DOM internals and layout assertions are outside the contract. The
currently unmodeled floating State note, Architecture variants and Sequence
variants are explicit source-backed diagnostics rather than skipped tests or
assertions that those gaps must stay present. A rejected reference input is
informational under the project's write-strict/read-generously policy; the
gate requires valid output for the supported writer cases.

For a baseline comparison, `AM_MODERN_TARGET_DIR` selects another Agentic source
checkout (with dependencies installed) while the tests and reference remain
unchanged; `AM_MODERN_GATE_REPORT` selects a different report destination. This
lets the same assertions demonstrate a regression against old code and pass
after a fix, without blessing expectations from current output.

Install the pinned Mermaid source and an independent reference outside this
repository (idempotent; CI runs the same script):

```sh
bun run reference:mermaid   # ../mermaid at the policy pin, ../mermaid-reference
bun run eval/mermaid-modern-compat/run.ts \
  --mermaid-dir ../mermaid \
  --reference-dir ../mermaid-reference \
  --pele-dir ../pele
```

`--pele-dir` is optional. It uses Pele's built entry point if present, otherwise its source entry point under Bun. This is the same corpus and input validation for both renderers, not an assertion that their appearance should match. The default output directory is `eval/mermaid-modern-compat/output/`, which is ignored. `--output PATH` changes it.

The source checkout must be clean and at its matching `mermaid@<version>` release tag, and its package version must exactly match the installed reference, with a major version of at least 12. Output records the checkout commit/tag, installed version, local starting and completion commit/dirty status and invocation. The current Mermaid 12.2.0 reference commit is `1fb7869866dd619168d840291c9c54b4f129758b`; the strict gates read that pin from the project policy. The standalone runner can assess another matching release of Mermaid 12 or later. Earlier 12.1 comparison reports retain their historical provenance. The harness does not change production dependencies.

All core syntax pages are included, even families Agentic Mermaid does not support. `examples.md` is not a family; external ZenUML is outside this core comparison. `info` is a separately labelled manual pseudo-diagram probe. Documentation fences are trimmed at their outer boundaries and deduplicated by the resulting source while retaining every file/line origin. Mermaid itself classifies accepted inputs by its diagram type; detector aliases collapse to canonical families. Inputs rejected by the reference remain visible and are excluded from support denominators.

For each input the runner records public `parseRegisteredMermaid` results, structured/opaque/preserved representation, `verifyMermaid` warnings, actual SVG rendering, finite coordinate checks, repeated-render determinism, and whether Mermaid accepts Agentic's serialized output. The standalone SVG renderer is checked even if structured parsing rejects the input. Preserved unsupported-family envelopes do not count as native parsing. Per-family counts and a mean of the 17 native families' rendering rates are reported alongside case-weighted totals.

Reference DB getter snapshots before and after serialization identify **conservative drift candidates**, not confirmed semantic losses. The original source is also parsed twice as a control: getters that change under that repeat are recorded and excluded from the serialization comparison. Generated commit identifiers, unordered maps and some rendering/config metadata are normalized; ordered semantic arrays are preserved. Getter availability varies by family, autogenerated counters/defaults may still differ, and an unchanged snapshot does not establish full fidelity. Snapshots cover serialization, not whether the SVG displays every authored element.

`authored-probes.json` holds separately aggregated diagnostic examples with upstream source references. Its duplicate-subgraph probe also requires the visible SVG labels `A` and `B`, detecting content loss that an unchanged serialization snapshot cannot detect. These authored probes never inflate the documentation sample count.

Add `--specs` to extract static string literals and template literals without substitutions from diagram spec/test files through the TypeScript AST. The runner never evaluates upstream code. Skipped interpolated templates are counted; other dynamically constructed inputs are not extracted or counted. Extracted literals can include test titles, expected CSS fragments and empty scaffolds that Mermaid's permissive detection also accepts. These are a diagnostic seed corpus, not an estimate of feature support or equivalent coverage of the upstream assertions. Spec results are aggregated separately; a full spec port needs family adapters that preserve the original assertions.

Add `--fuzz 100 --seed 7` for 100 globally sampled bounded mutations of reference-accepted inputs. The seed makes the mutation stream reproducible. Mutations are aggregated separately, including upstream rejection and permissive local acceptance; permissive acceptance is never a fatal failure. `FUZZ`/`SEED` are not environment options for this runner.

Outputs:

- `summary.json`: provenance, methodology, documentation denominators, per-family results, separate spec/authored/mutation results.
- `cases.json`: complete source, origins, local/reference outcomes, serialized source, snapshots, changed getter names and errors.

The evaluation records gaps and returns successfully when unsupported syntax or families are encountered. Installation errors, mismatched versions, a dirty reference checkout, or an unavailable reference process fail the run. This is a diagnostic tool, with no baseline expectations generated from Agentic Mermaid's current output.
