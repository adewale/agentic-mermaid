# Benchmark assessment

The suite is useful for finding compatibility defects, locating execution cost
and comparing tools at an explicitly named API or CLI boundary. It is not yet a
complete measure of Mermaid correctness, perceptual quality, production memory
or user cost. A single overall tool score would hide those differences.

This assessment separates source capabilities after the October 25, 2026 rebase
from the last published measurements. The maintained
[community scorecard](../../docs/community-benchmark-ranking.md) records the
actual revisions, versions and windows. Its broad community run attempted 84
catalog members and acquired/built 83 artifacts. The rebased catalog has 88
members; those four additional entries do not inherit measurements from the
older run. The [inventory](INVENTORY.md) lists the current executable boundaries.

## Changes prompted by this assessment

The [overview](OVERVIEW.md) describes the suite's current layers and contracts.
The following changes add evidence paths without rewriting historical results:

- The portable project campaign adds 49 authored cases: 23 family
  representatives, 15 scaling inputs, eight interacting-feature cases and three
  invalid inputs. Dave and the six-case fixed core keep their original roles.
- The Pele qualifier compares public-model identities, endpoint multiplicity
  and selected fields with independently authored expectations. Reviewed
  flowchart, class, state, ER and simple sequence paint projections add actual
  owned geometry, approximate attachment and scoped marker/label correspondence.
  Correctness preflight now fully checks the declared criteria in 28 positive
  cases; 18 positive cases still have unmeasured paint scopes. This count is not
  complete visual or Mermaid semantic fidelity. A failed canvas or label check
  also withholds semantic completion even when graph topology matches.
- First-use, repeated work, controls and resources have explicit separate
  protocols. The sampling plan requests five rounds and 20 fresh first-use
  samples per case/round; calibration still depends on the actual completed
  samples and control stability. Same-artifact Pele replicas qualify the
  method, rather than establishing a product speedup.
- Neutral benchmark execution has a concrete extraction boundary: the compiled
  portable program accepts an external project artifact without Agentic Mermaid
  source or Git. Source-stage diagnostics and repository-owned suites remain
  optional adapters with different prerequisites.
- Editor delivery, palette timing and the explicit Modern Mermaid application
  comparison are enrolled in the controller instead of being hidden standalone
  exceptions. Paid model/private skill workflows retain their external evidence
  requirements.
- Actual packed-package testing exposed the maintained community report being
  included by the public `docs/*.md` glob. The package excludes that benchmark
  report while retaining public API documentation; the reviewed shipping manifest
  does not need to admit benchmark material.

The remaining limitations below still matter when interpreting an observation.
New sampling machinery does not retroactively calibrate the older three-round
comparison, and a stronger flowchart oracle does not prove every family's
rendered meaning or perceptual quality.

## What we can trust

| Area | Judgment | Why |
| --- | --- | --- |
| Invocation coverage | Broad, bounded by its declared cells | Actual installed entries, runtimes, browser/worker/editor paths, Node/native CLI and MCP transports execute. The latest independent run retained 62,941 observations, including three real watch failures. This is stronger than inferring coverage from export names. |
| Language/reference coverage | Strong for the reviewed fixtures | Historical imported cases and current pinned Mermaid are kept distinct. Current same-case scoring checks independent criteria and records parser time separately. Negative, mocked/internal and disabled upstream cases retain explicit diagnostic scope. |
| Family breadth | Broad routing and stimulus coverage | The latest family corpus spans 23 families and 994 inputs. Existing owning tests add mutation, serialization, route and rendering assertions. Their passes are not automatically credited to every operation or transport. |
| Community comparison | Useful within matched lanes | Catalog members, acquisition failures, source aliases and public boundaries stay visible. Fixed core inputs do not shrink to whichever inputs each tool happens to pass. CLI, browser and library timings have separate ranks. |
| Regression qualification | Sound protocol, incomplete latest calibration | The maintained semantic protocol has two A/A controls, consumed outputs, exact archive/dependency admission, per-case gates and a bounded noise policy. The latest completed comparison was explicitly uncalibrated. |
| Delivery evidence | Useful for deployment choices | Initial bytes, first interaction, full requested closure, compressed payload and compiled/interpreter scopes are distinguished. A tiny lazy entry cannot hide the cost of the first render. |
| Failure/provenance handling | Useful and unusually explicit | Failed, unsupported, blocked, N/A and unavailable outcomes remain distinct. Repairs retain originals and identify exact replaced rows. Git revisions identify own source; hashes identify fetched or shipped bytes. |

The strongest check on self-congratulation remains the pair of external
comparisons. The latest Dave run accepted **823/1,095** cases for Agentic Mermaid,
versus **1,063/1,095** for Pele. The reviewed pinned-Mermaid score was
**2,479/2,607** criteria, versus **2,607/2,607** for Mermaid. These numbers expose
different gaps: returning SVG is a weaker promise than retaining the checked
meaning of a diagram. Neither number is a complete visual quality score.

## What is missing or weak

### Operation and feature coverage is incomplete

Only **44/279 advertised family–operation kinds** had direct packed-package
witnesses in the published run. Existing owning tests exercise additional
behavior, but the mapping from those tests to public operations is incomplete.
Direct invocation of exported builders, queries, registration hooks and helpers
is also thinner than entry-point and transport coverage.

The next useful work is a bounded operation contract map with independent
expectations for writes, rejected writes, identity/source preservation and output
correspondence. Running every fixture through every transport would be expensive
and would repeat many assertions; targeted combinations should cover transport
serialization and features that can change behavior across boundaries.

### “Valid output” is weaker than faithful output

SVG XML, positive canvas and authored-text checks reject obvious invalid or
empty output. They do not prove correct endpoints, edge multiplicity,
attachment geometry, group ownership, clipping or legibility. The carefully
scoped empty-fixture N/A repair illustrates why admission must follow the input
contract rather than treating every zero-size diagram as either a pass or a bug.

PNG signatures and dimensions similarly establish an image container, not a good
drawing. Own geometric/paint/terminal contracts and reviewed image evidence need
more enrollment across community adapters. Mermaid geometry should remain a
comparison observation rather than our pixel specification. Perceptual judging
needs independent human or model evidence; deterministic quality-metric mocks
cannot validate the metric they reuse.

### Competitive timing is narrower than family breadth

The main community speed aggregate uses six core inputs from five families.
The wider feature corpus mostly receives one qualification call, not repeated
speed samples. It therefore supports breadth observations but not an all-family
speed claim. Tiny graphs, exact-repeat paths and a sum dominated by one large
case can each favor different engines.

Add separately named balanced per-family and scaling cohorts with small/medium/
large inputs, deep nesting, parallel/reciprocal edges, long/wide Unicode labels,
configuration changes and invalid-source recovery. Keep the original Dave and
fixed-core cohorts stable so historical comparisons stay interpretable. Report
per-case distributions alongside aggregates; do not replace an adverse case
with a favorable geometric mean.

### Most small PR differences remain advisory

Three rounds and observed paired-control bands support useful diagnostics, not
strong significance claims. The latest semantic comparison had three rounds
where its policy requires at least five, leaving 552 checks uncalibrated. Fresh
first-use p95 needs at least 20 independent samples per round, and cold
allocation needs its own probes. Several peer adapters cannot expose complete
semantic identities/endpoints, so their label-checked timing cannot qualify
semantic equivalence.

Counterbalanced repeated controls, retained individual calls and explicit noise
ceilings are preferable to inventing a universal “within 5%” pass rule. The
optional layered backend in PR #449 also needs an explicit treatment; default
API clocks say nothing about that backend's speed or quality.

### Memory and model costs are not complete

Audit demonstrated that a child API process's `maxRSS` can inherit its parent's
historical high-water mark. Those raw fields are excluded from rankings. End RSS
is still a runtime/harness snapshot after unequal adaptive work, not peak memory
per equivalent render. Browser V8 heap excludes native/WASM/GPU allocations.

The separate fresh CLI GNU time pass provides attributable child peak RSS and
CPU for a fixed cohort, with reporting-grain censoring. API memory still needs
fresh comparable processes, baseline subtraction or a documented process-tree
observer, and separate native/WASM coverage. Retention/leak slopes, concurrency,
long-running sessions and deployed worker limits need more attention.

Live model evaluations require real task transcripts, provider/model identity,
token usage and dated prices. Missing credentials or transcripts mean
unavailable evidence. Stored replay success and zeros in a coarse CPU counter
must never become a claim of zero dollar or compute cost.

### Historical and cross-project ranks need scope discipline

The broad community, latest-main invocation and PR campaigns used different
frozen revisions and windows. Source-equivalent forks share evidence, rather
than adding independent votes. Conflicting PR heads use their own bases and
cannot be ranked as integrations on current main. A renderer, parser-only tool
and full application should not share a latency table without naming the
different boundaries.

Reusing unchanged results is appropriate, but the table must retain each
project's measured version, time, host/runtime and protocol. An updated project
beside older peers is a rolling record. A strong claim of a new cross-project
performance win still needs a matched comparison window when machine drift can
affect the conclusion.

### Automation and extraction need explicit boundaries

Before this change, benchmarking code was typechecked through the product's
repository configuration, unified harness tests lived among product tests, and
hosted workflows could execute timing campaigns. Product correctness checks
should remain independently runnable in CI while benchmarking stays an explicit
local/offline operation.

The unified runner also imports the Agentic family registry, fixture builders,
source types and display helpers, reads repository policy/catalog documents, and
discovers product scripts and owning tests. Keeping these dependencies in named
Agentic adapters makes later extraction possible, but a dedicated package alone
does not make every suite standalone. The extraction acceptance test should copy
the neutral harness into an empty workspace, supply the catalog/artifacts and
Agentic adapter explicitly, then list/run a selected community project without
requiring product source or its development dependency tree.

### “All suites” still needs a precise definition

The controller list includes correctness and preparation alongside performance.
Editor delivery and palette timing now have controller entries; portable project
and Modern Mermaid application campaigns need explicit inputs. Private
skill/model workflows and callable external judges retain their separate
evidence requirements. The inventory makes these boundaries visible. Missing
prerequisites should remain blocked records rather than silently omitted jobs.

The most useful next benchmark work is to improve direct operation and semantic
oracles, then qualify a small representative performance cohort with sufficient
independent controls. Another large count of weakly checked renders would leave
the current correctness and attribution gaps intact.
