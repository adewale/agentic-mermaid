# Local layout runtime review

Benchmarks run only in an explicitly owned local session. CI, scheduled jobs and
hosted manual workflows are excluded by the benchmark package policy; the former
release and layout-runtime-review workflows have been removed. Existing hosted
reports retain their historical meaning and are not new qualification evidence.
Static SVG/PNG backend review artifacts remain available in ordinary CI.

Build the candidate and immutable integrated native23 baseline before measuring,
record both revisions and their package/lock/JavaScript hashes, and run from the
repository root. Do not run competing builds, tests or measurement workers.
Generate the historical27 input envelope with
`bun run eval/benchmark/layout-review-population.ts`; retain its complete output.
The direct driver below accepts that envelope through `--inputs`.

The local release canary uses `eval/benchmark/release-bench.ts` with
`--candidate /path/to/built-package --layout-modes elk,agentic,agentic-with-elk
--layout-cache off --layout-reference batched --rounds 3 --reps 25
--budget-ms 480000 --case "$(bun run eval/benchmark/layout-review-population.ts --case-list)"
--out /path/to/fresh-results`. Repeat with `normal` and a separate fresh directory.
Both cache policies retain their fixed populations, controls and per-policy
shared bounds. The Architecture supplement uses the separately generated
`--architecture-supplementary --case-list` selection and remains outside the
historical27 denominator. Run optional churn using the local command below;
there is no hosted-CI override. Retain all failed, timed-out and unlaunched rows.

The direct runtime driver compares native23 to an independent native23 A/A and native24, plus candidate ELK to native24. It uses existing release workers, batched mixed-workload timing, independent matched memory, quality reruns, gates and failure handling. It does not reinterpret `release-bench --baseline`, which compares an older default ELK path. Extra fallback and current-main ELK arms are optional and must be declared before launch; they share the same480000ms deadline.

```bash
bun run eval/benchmark/layout-runtime-differential.ts --baseline /path/to/integrated23 --candidate /path/to/final24 --layout-cache off --out /path/to/new-results-off
```

Repeat with `normal` and a new output directory. `--inputs` accepts the JSON generated by `layout-review-population.ts`, retaining full source/label/workflow metadata and hashes; without it the driver constructs the historical27 directly. It refuses changed round/repetition/deadline values and nonempty output directories. `--include-fallback true` adds a direct fallback23→fallback24 comparison. `--main-elk /path/to/main-package` adds mainELK→native24 and mainELK→candidateELK. A/A controls are checks, never ratio divisors. Output and receipt equality are reported separately because implementation changes intentionally alter receipts.

The memory-only churn driver preserves the exact historical96 source generator. The129/256 populations use a separately declared generator with monotonically longer `W` labels, rather than digit changes, to target different measured node widths. They do not inherit historical96 shape-comparison claims. Actual measured-key cardinality is checked by the source probe. The driver supports dist-only packages using the current stable harness path. An optional old-native artifact adds old-native A/A and old→new memory comparisons.

```bash
bun run eval/benchmark/layout-cache-churn.ts --candidate /path/to/final24 --baseline /path/to/integrated23 --population 96,129,256 --layout-cache normal --diagnostic-source /path/to/final-source --out /path/to/new-churn-results
```

Its480000ms bound covers all selected populations, rounds, arms and optional source diagnostics in that cache regime. This is `bounded-cache-churn@2`, not the old per-worker-deadline protocol. It makes no render-time claim. GC-boundary estimated allocation/heap, one-pass retained growth and whole-worker RSS remain distinct measures. Failed or missing rounds remain explicit and cannot yield a complete ratio.

The optional cache counters are evaluator-only source transformations. They instrument WeightedLru and native result caches without editing production source, adding public APIs, or setting diagnostic globals. An uninstrumented source bundle runs the same inputs in a separate fresh Bun process; complete SVG/receipt hashes must agree. Fixed-shape transforms fail closed on source drift. Counters report hits, misses, sets, evictions, rejected retention, current weight and entry count per cache instance, plus SHA256 fingerprints and cardinality of actual get/set keys; the report labels the cache layers and their weight units. The129/256 solver-churn check requires at least the intended population of distinct geometry get/set keys and observed evictions with the outer cache disabled. A shortfall fails that diagnostic. No source instrumentation timing/allocation result can be used as a release performance result.

The96 population can fit the outer128-entry cache and therefore mask inner64-entry solver-cache churn. The source diagnosis includes normal outer+inner (`EXPERIMENTS=text-spans,position-cache`, `ELK_CACHE=1`), outer-off/inner-on (`EXPERIMENTS=text-spans`, `ELK_CACHE=1`), and a separately launched global cache-off regime (`ELK_CACHE=0`). Global cache-off also disables the outer cache; it cannot isolate outer-only caching. Each counter probe includes fill, second and third passes. Read differences between successive snapshots; counters are cumulative, and no extra render is hidden inside a reset.

Build both packages before all campaigns, record their source revisions, and do not run builds, tests or other timed workers alongside measurements. Retain every timeout, typed decline, report and previous attempt. A workflow or artifact existing is not evidence of completion: inspect campaign status, all planned rounds, support outcomes, A/A gates and matched memory. This is the27-case release canary and declared supplementary evidence, not proof of every Mermaid family or all generated inputs.

## Separate whole 27-input memory experiment

`layout-memory-only.py` declares and runs a separate mixed-session experiment
against two already built packages. Each stock release memory worker receives
all 27 historical inputs, including the edit workflow. This measures a whole 27-input
session, unlike the legacy release harness's pooled seven-corpus worker and
separate scaling/edit memory workers. It does not replace failed legacy
qualifications or establish timing results.

```bash
python3 eval/benchmark/layout-memory-only.py declare \
  --baseline /path/to/integrated23 --candidate /path/to/final24 \
  --worker "$PWD/eval/benchmark/release-bench-worker.ts" \
  --inputs /path/to/full27-inputs.json --out /path/to/new-memory-results
python3 eval/benchmark/layout-memory-only.py run --plan /path/to/new-memory-results/plan.json
```

Use a Node version supporting TypeScript stripping. The input is the historical27
envelope from `layout-review-population.ts`; the retained final experiment
includes its exact bytes. Declaration freezes driver, Node, worker closure,
input and package/lock/Node-JS hashes. Execution refuses changed artifacts or a
previously executed plan. Both cache policies run serially; each has three rounds,
five fresh-process arms (ELK, ELK A/A, baseline native, baseline native A/A,
candidate native) and one unchanged 480,000ms shared bound. Worker order rotates
by round. Run without competing builds, tests or benchmark workers.

Memory mode ignores the positive `reps:25` protocol field: it warms one pass,
measures per-input GC boundaries, then measures one complete mixed-session pass
and its settled growth. RSS covers the worker lifetime. Complete SVG and receipts
are consumed, but this worker mode does not expose their fingerprints. Pair the
memory evidence with separate correctness/determinism evidence. Pass-allocation
and RSS A/A median ratios must lie in reciprocal 1.1; candidate growth gates are
1.25× and retained growth has a 16MiB absolute cap. Retained ratios with zero
denominators remain null. All granular values, failures and unlaunched rows stay
in the report, including individual inputs/rounds outside aggregate controls.

The [recorded experiment (gzip JSON)](../../docs/design/system/layout-guidance-benchmarks.json.gz)
contains the immutable declaration, exact executed driver bytes, input envelope,
all 30 results and assessments. The portable runner subsequently narrows only
its malformed-result exception handler for lint; its hash is recorded separately.
No measured renderer or stock worker changed. Never use this new protocol to
relabel a deadline failure as a passed release qualification.

## Optional native-only cost pilot

`layout-change-ablation.py --native-only` declares three arms: baseline native,
independent baseline native A/A and candidate native. Its default remains the
four-arm experiment including ELK. Both modes retain three rounds, 15 timing
repetitions, both cache policies, the explicitly supplied population and the
stock full-consumption worker. The native-only summary omits ELK ratios because
it does not measure ELK. Its 36 planned worker slots and omitted arm are recorded
in the plan. It is a cost pilot, not the 25-repetition release qualification.

`--budget-seconds` bounds the entire pilot, including both cache policies;
`--timeout-seconds` additionally bounds each worker. These differ from the
release campaign's 480,000ms per-policy shared bound. Declare populations,
acceptance targets and limits before launch. Retain interrupted experiments and
unlaunched slots; a separately declared experiment does not repair them.
