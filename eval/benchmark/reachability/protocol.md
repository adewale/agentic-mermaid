# PR 469 packed public decision measurement protocol

This focused experiment measures public API delivery from verified packed packages; it does not replace canonical release qualification. Freeze configuration and this runner before timing. Run on one otherwise idle host with no concurrent builds or tests. Record the exact final source revisions, tarball SHA-256, runtime and frozen dependency installation. Use Node 24.20.0, Bun 1.4.2 and npm 11.18.0 for the recorded reproduction; different runtimes require separately identified evidence.

## Inputs and boundaries

The default fixture inventory covers empty flowchart, one zero-edge node, sparse eight-node disconnected edges, 50/150/400-node chains with authored feedback, a 50-node branching feedback graph, nested scopes with feedback and external endpoints, and a 20-message Sequence negative control. These are newly named public fixtures, not exact replays of the unavailable original owner runner. The empty input's actual success or refusal is recorded. Refusals are fingerprinted and excluded from speed/allocation ratios.

Two endpoints are measured: `renderMermaidSVG(source)` plus TextEncoder UTF-8 encoding; and `renderMermaidSVGWithReceipt(source)` followed by TextEncoder encoding of its complete SVG and `JSON.stringify(result.receipt)`. This matches the maintained micro benchmark's consumedCase boundary and avoids serializing an additional escaped copy of the SVG. Receipt serialization fully consumes receipt properties. Encoding traverses all delivered SVG bytes; a length/final-byte sink keeps the materialized bytes observable. SHA-256 hashes of complete encoded SVG bytes and complete serialized receipt are computed outside clocks. No receipt fields are stripped or normalized.

Each endpoint runs in exact-repeat and semantic-new-source regimes. Repeat uses the same source after warmup. New-source changes the first node/participant's visible label, creating a different ELK model key for every warmup and measured call. Namespaced endpoint/phase tokens prevent cache-on receipt rows from reusing SVG-row keys. Tokens and their widths are identical across baseline, candidate and A/A. This stresses cache misses without relying on comments that might leave layout keys unchanged. The empty fixture has no semantic-new-source row. New-source inputs have slightly different output text; full equality is checked only between matching tokens.

ELK cache policy is explicitly off or on in fresh processes; scene assertions are explicitly off to match the maintained release benchmark. Feature policy defaults to production defaults by removing AGENTIC_MERMAID_EXPERIMENTS from child environments; an explicit empty string would disable all three normally enabled selected mechanisms, including position-cache. Cache off disables both ELK caching and the positioned-artifact cache; cache on repeats therefore measure ordinary position-cache hits as well as ELK policy. Semantic-new-source labels force both keys to miss. The two policies and both regimes are reported separately. JIT/import/cold-start effects are not claimed as warm rendering gains: import duration is recorded, two untimed deterministic oracle calls plus at least two warmup calls and 80ms warmup precede samples by default. The minimum duration can produce different warmup populations between arms; preserve these counts. A separately configured confirmation uses exactly twenty warmup calls and warmupMs=0, with the six control caseIds described in README.md; never pool it with the original screen. The default five timed calls are separate samples, not batches. APL_* feature overrides, if present, are recorded explicitly in the manifest; other unrelated host environment values are not copied into evidence.

## Pairing and evidence

Per mode/cache block, seven fresh baseline/candidate process pairs alternate execution order. Three baseline/baseline A/A pairs are interleaved among candidate pairs, also alternating order. Timing blocks finish before allocation blocks; workers execute serially. An A/A or candidate worker runs the same row ordering. Per-row metrics are within-worker medians; reported ratios are medians of seven same-round candidate/baseline ratios (three for A/A). Raw samples, signed deltas, ratio ranges and slower-round counts remain available. Different endpoints, policies and workloads are never averaged into one headline speedup.

The driver requires the independently generated passed acquisition.json receipt and checks its source/artifact/root identities, runtime and current lock hash. It verifies each supplied archive hash and freshly extracts that archive for measurement, checking every acquired packed file hash and recording every dist file hash and the package metadata hash. Both extracted packages resolve dependencies through the same separately frozen installed node_modules tree; its resolved location and configuration are recorded. Acquisition.json includes the independently inspected production dependency closure and is copied into evidence. All runner sources and protocol are copied into the output. Optional config.caseIds selects a nonempty unique subset of the same fixture definitions, and the manifest/worker inventory use only that selection. The entire run fails qualification if a worker fails, row inventory changes, output/status differs, sample counts differ, or a metric is invalid. Invalid comparisons are excluded from ratios. Original failures and refusals remain in outputs.

Every successful row has exact paired full-output equality checks for two pre-timing calls, every measured sample, and a final post-churn call. Within-worker oracle output must remain deterministic before and after churn. Fingerprint agreement is a differential preservation check, not an independent semantic SVG oracle. Existing independent correctness and canonical release gates remain required.

## Allocation limits

Allocation uses separate fresh workers and one observation per row per process (seven paired observations plus three A/A pairs). The estimator copies the maintained `eval/benchmark/bench-stats.ts` GCProfiler method: positive V8 used-heap increments before/after observed collections plus final heap displacement. Forced GC occurs before starting each untimed observation; no allocation profiler or forced GC runs in timing workers. The measured callback includes rendering, complete receipt JSON serialization when applicable, and SVG UTF-8 materialization. Results are V8 heap allocation estimates, blind to external typed-array backing stores, WASM and native allocations. They do not establish peak or retained memory. Whole-worker RSS covers all rows/import/warmups, so it is recorded only as process metadata, never attributed to a case.

## Decision rules and reporting

Do not call this a complete qualification or a broad release speedup. Preserve all adverse rows. Preregister a focused timing concern when the median ratio exceeds 1.05, at least six of seven candidate pairs are slower, and the median ratio displacement and median absolute delta each exceed the maximum respective absolute A/A displacement/delta. Report direction/count even when noisy A/A prevents attribution. Use an analogous allocation diagnostic above 1.02 with at least six of seven paired increases and both A/A comparisons satisfied; also disclose any all-round allocation increase below that threshold without claiming tiny GC-boundary differences are exact. For beneficial rows, show paired direction, absolute milliseconds, and the matching A/A envelope; an owner-level gain alone cannot justify public claims. These are preregistered diagnostic flags, never automated selection or a replacement relaxation of existing gates. A landing recommendation still requires unchanged payload caps, full maintained release qualification, output preservation, and a concrete worthwhile benefit or consistency benefit without material public regression.

Invocation from the repository root: `node eval/benchmark/reachability/run.mjs --config CONFIG.json --out NEW_OUTPUT_DIRECTORY`. Configuration supplies `acquisitionPath`, optional `node`, `featurePolicy` (default `default`), optional top-level `caseIds`, and optional `settings`. Baseline/candidate identities default to the acquisition receipt; explicit overrides must match it. See README.md for relative-path configuration examples and artifact preparation. Freeze each configuration before execution; deviations and post-screen confirmations need their own identities and outputs.
