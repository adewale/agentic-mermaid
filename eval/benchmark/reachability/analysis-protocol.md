# Packed public analysis API supplement

This separate experiment follows discovery that public `analyzeMermaidSource` and `analyzeMermaid` call route classification without ELK/SVG rendering. Original focused SVG/receipt observations cannot establish absence of benefit on these distinct public endpoints. This supplement does not overwrite or pool those results, and makes no allocation claim.

Before execution freeze this protocol/configuration. Use the same independently acquired baseline/candidate packages and frozen dependency tree as the rendering experiment. The driver checks archive and every acquired packed-file hash, lock identity, shared dependency root and passed acquisition receipt. Runtimes are Node 24.20.0 and Bun 1.4.2, recorded separately. Production feature defaults apply; scene assertions and ELK cache flags are zero. These APIs do not invoke ELK; cache policy is not an analysis optimization arm.

Use the unchanged public fixtures with their original `repeat` label: empty flowchart, sparse8, branch-feedback50, chain-feedback150 and chain-feedback400. Both public endpoints fully serialize all returned facts via JSON.stringify and UTF-8 encode them inside the measured callback, with an observable byte sink. `analyzeMermaidSource` includes source parsing and its public Result wrapper. The parsed arm obtains one `parseRegisteredMermaid(source).value` outside all warmup/timing and calls the public `analyzeMermaid` on that reusable object. No result cache, private import or extracted owner substitutes for either endpoint. The source API's successful `.value` must equal parsed API facts independently before timing; exact full returned bytes are compared only within the same endpoint.

Each worker uses two untimed complete-output deterministic checks, exactly twenty warmup calls, then five fixed-size timed batches. Per-sample metrics divide measured batch duration by the preregistered count: empty=1000, sparse8=200, branch50=50, chain150=20, chain400=10. These fixed counts are frozen without a calibration run. Every call inside a batch fully consumes its facts. Full final-batch output hashes are computed after the clock; the complete initial and post-batch oracle hashes must agree. We do not hash each interior call inside the timed batch or retain all interior outputs, so this is a repeat-output differential guard rather than an independent semantic proof for every interior call. Refusals and errors remain evidence and invalidate performance qualification; they never count as fast analyses.

For each runtime run seven fresh baseline/candidate process pairs with alternating order; interleave three baseline/baseline A/A pairs after candidate pairs two, four and six, also alternating order. All forty workers run serially, with no competing tests/builds/benchmarks. Report within-worker median per-call duration, then median paired candidate/baseline ratios, signed absolute deltas, paired direction, and A/A displacement separately for every runtime/fixture/endpoint. Do not average endpoints/runtimes, extrapolate synthetic scaling gains to normal workloads, or combine with prior SVG ratios.

The unchanged diagnostic for adverse timing requires median ratio above 1.05, at least six of seven slower pairs, and both ratio displacement and absolute delta beyond the maximum respective A/A displacement/delta. This flags investigation, never automatic selection. Beneficial findings require inspection of paired direction, absolute duration and matching A/A envelope; no retrospective acceptance threshold substitutes for unchanged bundle caps/full release qualification. Even a clear analysis benefit does not erase adverse SVG/receipt/payload observations.

Run when the host is idle: `node eval/benchmark/reachability/analysis-probe.mjs CONFIG.json NEW_OUTPUT_DIRECTORY`. Raw jobs, outputs, process exits, acquisition, exact input strings, copied runners/config/protocol and summary are retained. This bounded focused supplement is separate from full release qualification.

The repository-native runner reuses `fixtures.mjs` from the same directory; its fixed five-case selection contains no second source table. Configuration paths resolve from the invocation working directory. See README.md for a relative-path configuration example and artifact preparation.
