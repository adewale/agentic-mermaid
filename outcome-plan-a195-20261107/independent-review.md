**No blocking correctness finding in this change.** The implementation satisfies the stated reuse and broad-phase contracts in the current control flow.

- **Invalidation is conservative (layout.ts:1443–1450, 1612–1636).** Initial canonical contacts and initial caption finalization precede the first snapshot. Every committed face movement sets `changed=true` and rebuilds the retained snapshot. Because `changed` is sticky, subsequent frame/caption repair always prevents final reuse, even if the last face snapshot would otherwise be current. The failed-caption repair branch likewise prevents reuse: its final `finalizeErRelationshipLabels` return is not assigned back to `failedCaptions`, so the branch's initially nonempty array remains nonempty at the guard. No route-changing repair is reachable after a reused final snapshot is selected.
- **Aliasing is safe within this scope.** Glyph `point`/`toward` and straight-shaft `line` entries refer to route points, while pieces/bounds are derived snapshots. Face repair copies/replaces point arrays and marks the epoch changed; later frame repairs can mutate routes but are covered by the guard. With reuse enabled, downstream `erSimpleRoute`, obstacle tests, terminal-depth tests and label checks read geometry rather than mutate it. Labels are freshly boxed regardless of snapshot reuse. The data stays call-local; no new cross-call cache or externally reusable proof object is introduced.
- **Union queries preserve collision coverage (layout.ts:1677–1721).** `erCardinalityInk` rejects nonfinite piece bounds; each retained glyph bound is the componentwise min/max union of all pieces. Any strict intersection of a piece with an obstacle/shaft therefore implies a strict intersection with the union. Broad-phase querying the union cannot omit an earlier piece collision. False positives in gaps are rejected by the unchanged charged `intersects` predicate inside `pieces.some`. Own-entity/group distinctions and the exact first/last incident-shaft exclusion are unchanged. Terminal length/normal checks still precede these queries; corner-only terminal rejection is retained.
- **Index reuse retains exact geometry and metering.** The shared index lazily builds from a copied item array and reads retained immutable bounds; it does not mutate glyph/shaft geometry. Exposing `currentShafts` and `bounds` does not create another roster: those objects were already retained by the query closures. Reusing them removes actual regeneration/index work. Query visits and exact intersection tests continue charging the existing shared allowance; the 400,000 cap is unchanged.

## Nonblocking resource caveats

The retained face-phase index was constructed with `expectedQueries=currentGlyphs.length`. A fresh final index previously used `glyphs+labels` or `4*glyphs+labels`. Reuse preserves the original index's scan-versus-tree decision. Consequently, for some many-segment/small-glyph cases, it can keep linear scans where a fresh final index would choose a tree. That affects efficiency, not collision correctness, and every visit remains charged. Union bounds can also return candidates lying only between pieces, increasing exact checks. Cardinality pieces are bounded by the current vocabulary (at most four), but neither change guarantees lower work for every geometry. Existing refusal boundaries and broad-corpus evidence should remain visible; do not claim universal performance improvement.

The coordinator reports snapshot-only and union-only BT refusals, combined success for all eight backend/direction products, and owning-matrix RED4→GREEN. Those runs were not repeated here. Existing frame/rounded-route/contact suites are relevant to the fallback path, but this static review does not claim branch coverage or an independently verified corpus result.
