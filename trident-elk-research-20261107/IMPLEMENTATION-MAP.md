# Mermaid implementation families: ELK, alternatives, tests and cost boundaries

7 November 2026. Discovery used Trident's pinned [community catalog](https://github.com/adewale/trident/blob/f080278e31e4202ca89d524e4ee9e4cf3cbff038/catalog/mermaid-community.json). Revisions below are the inspected sources, not assertions about the code inside every published artifact. Full acquisition outcomes are in the JSON receipts.

## Engine families

| Implementation / inspected revision | How it uses or replaces ELK | Correctness mechanisms worth learning | Performance mechanisms and limits |
|---|---|---|---|
| [Mermaid 12.2 source](https://github.com/mermaid-js/mermaid/tree/1fb7869866dd619168d840291c9c54b4f129758b) | ELK is a layout alternative, not the whole Mermaid renderer. Adapter prepares measured nodes/labels, runs elkjs and projects geometry through common rendering. Dagre and other family-specific paths remain. | Adapter tests for arrow semantics, exact shape-outline attachment and option propagation; common DOM measurement ties sizes to actual rendered labels. | Loadable layout plugin avoids requiring all solver code up front. DOM/fonts and consumer work remain costs. `await elk.layout` does not itself establish parallelizable independent work or worker execution. |
| [Beautiful Mermaid](https://github.com/lukilabs/beautiful-mermaid/tree/2ac8bbbb060ca0a65a6a21f3200bd99b1587b488) | Uses ELK layered for graph families, own parser/text geometry/SVG consumer; terminal ASCII has its own geometry. This is our ancestry, not an independent replacement. | Explicit conversion and disconnected-component non-overlap tests. Many lessons are already inherited. | Synchronous FakeWorker bypass removes asynchronous scheduling wrappers; it still runs ELK. Lazy singleton does not remove static bundle dependency. Internal-worker coupling is an integration liability, not an algorithm optimization. |
| [Zombie Mermaid](https://github.com/dfadler/zombie-mermaid/tree/8cc982128bed11d976fb38164c4cdb47be7bd34d) | Maintained Beautiful fork; separates core/parser/ELK layout/renderers. ELK becomes an explicitly registered optional peer for families requiring it. | An absent registered solver gives `ElkNotRegisteredError`, not an invented fallback layout. Migration/source tests preserve explicit behavioral changes. | Strong concrete packaging lesson: consumers that do not need ELK need not import it. Its own guide's byte figures were not remeasured here. Selecting a backend at runtime alone is insufficient to remove bundled code. |
| [Pele 1.13](https://github.com/obsidianmd/pele/tree/3a2f075ee0c3d914f0fad3545fc0f193693975ac), separately [1.9 tag](https://github.com/obsidianmd/pele/tree/e7f092a4de147cc32210913c20e36eaa5fcd0ef1) | Independent TypeScript measurement/layout/SVG implementation; no ELK runtime. Layered layout, offset-aware alignment, compound port handling, conditional rank doubling (long edges still normalize). Current source targets Mermaid12.1 syntax. | Compound port order and alignment tests; independent segment crossing counts; actual renderer contact/marker tests; syntax/model compatibility suites. Current behavior differs from1.9. | No library runtime dependencies, synchronous API and family/lazy exports. Static closure compressed-size accounting is useful. Browser font lifecycle and default curves differ from Native. Direct curves under dummy pressure change obligations rather than proving equal-work capacity. |
| [Ondine](https://github.com/wevm/ondine/tree/439fc64aefdb06e3451fac6c44266e5965ea7265) | Rust/WASM port of Pele's layered/compound design; layout source explicitly credits that origin. Not independent confirmation of the algorithm. | Mermaid12.1 accept/reject/type/model oracle; seeded mutations; documented divergences; Pele-derived vectors with provenance. These are parser/model checks, not proof of ink. | Build-time SVG compilation moves work out of viewer startup. Opt-in family WASM modules optimize size; Node `all.fast` optimizes speed. Compiler/runtime split and actual deployment boundary matter more than “WASM” alone. |
| [Bezel Mermaid crate](https://github.com/crabtalk/bezel/tree/25b1da54115d3253d457d6c1fb3f62c05261dd13/crates/mermaid) | Rust Pele-derived Mermaid renderer within a native GUI toolkit. | Captured Pele parse compatibility plus SVG/native-consumer tests. Useful for bugs in translation or platform assumptions; shared ancestry limits oracle independence. | Native integration can avoid browser startup. Its benchmark loop follows Pele's mesh generator; that is not an equal-boundary Native proof/receipt benchmark. |
| [mermaid-rs-renderer](https://github.com/1jehuang/mermaid-rs-renderer/tree/3726ccbffe0e8032361eb9668694b24f77858060) | Independent Rust parser, layout, routing and output, without ELK dependency in inspected Cargo manifest. Flowchart pipeline analyzes relationships and reserves label/hub/boundary space before routing. | Stage reports, semantic/invariant/robustness suites, byte determinism and small-edit displacement. Public malformed IR and finite-coordinate tests are useful. Some stage checks are debug-only; determinism skips initial parse failures, so it is not a delivery test. | Avoids browser machinery; system-font face caches and an optional fast ASCII text approximation change cold/warm and geometry boundaries. Marketing ratios against mermaid-cli mix process/browser work and must not be imported into our comparison. Its complex repair pipeline is not evidence all repeated passes are gone. |
| [Merman](https://github.com/Latias94/merman/tree/252752f7029b67f6a6f22a35230ef2bdf9c605d0) | Rust Dagre port (`dugong`) **and source-backed ELK layered port** in an isolated EPL crate, plus adapters. A language replacement need not be an algorithm replacement. | Source references per translated phase, actual elkjs parity fixtures, typed unsupported/interrupted outcomes, pre-mutation work admission. Kernel existence is explicitly distinguished from renderer feature support. | Build features omit compiled ELK when wanted; runtime Dagre selection cannot do that. Stable indices and explicit graph transformations aid auditability. No equivalent-work timing or memory ratio established here. |
| [Frankenmermaid](https://github.com/Dicklesworthstone/frankenmermaid/tree/29536a1308acd1bae4da8b72b4cebffb39709ae0) | Independent Rust layout/rendering ecosystem with many experimental mechanisms; catalog artifact/source dates differ. | Interesting test ideas: minimize failures, deterministic faults, and compare incremental versus full recomputation across work-budget thresholds. A warm seed plus a bounded optimizer can change output even when small tests agree. | Source complexity, optional incremental mechanisms and cache machinery are not evidence of a performance win. License has a restrictive rider; no code/test copying or execution proposed. Learn the general failure pattern, not this framework. |

Editors, preview apps, bindings and forks in the remaining catalog should be classified by their underlying solver before counting them as algorithm evidence. The terminal/grid renderers have a different output geometry and are not interchangeable SVG layout wins.

This is a host lifecycle concern. Native's deterministic synchronous font-profile contracts should not inherit ambient browser mutation by accident.

## Cache and packaging lessons

Observed examples are not evidence all caching is harmful. Beautiful's singleton amortizes solver initialization; mmdr caches font lookup and disk font-face discovery; Ondine caches builds by their complete input hash; Pele's browser measurement state must respond to font loading. These have different validity domains. Separate cold process/init/font discovery, repeated render, and edit measurements before judging them.

The algorithmic alternatives are to avoid unnecessary intermediate geometry, represent long edges sparsely and finalize owned geometry once. The packaging alternatives are optional solver registration, actual family module boundaries and build-time compilation. Neither requires another render-result cache. Native already has lazy solver boundaries; prove an unwanted dependency is in the emitted static/request closure before proposing another split.

No third-party upstream suite was run during this research. Selected source inspection, Trident execution receipts and Astra's small executed Native probes are distinct evidence types.
